# 外部监控器覆盖验收

截至 2026-11-12，独立 Windows 自检可运行。这里的 99% 是接入后真实任务的验收目标。当前接入后的独立真实任务样本数为 0，覆盖率未知。模拟 job 宿主和合成验签只用于检验机制。

## 去重场景矩阵

按主要触发条件划分。一条真实任务可以触发多项，但只进入真实任务分母一次。

| ID | 触发条件 | 期望可观察行为 | 本地证据 |
|---|---|---|---|
| L01 | 锁空闲，首个会话申请 | 立刻预留；领取前无 SW 命令许可 | 自检 |
| L02 | 三个房间竞争 | FIFO，释放后只有队首等待 job 完成；队尾仍等 | HTTP + 模拟 job 宿主 |
| L03 | 等待 job 被取消 | 未领取票撤销；实际 CAD job 继续；其他票顺序不变 | HTTP + 模拟 job 宿主 |
| L04 | 队首超时未领取 | 预留过期让给下一位，旧票迟到不得领取 | 自检 |
| L05 | 实际后台命令仍在运行 | 在途命令挡住释放；同票不能并发 begin 或重放命令 | 自检 |
| L06 | 另一会话或任务使用旧票 | 票按 epoch、任务、房间、会话绑定，冒用被拒 | 自检；跨任务真机待测 |
| L07 | SW 未启动、退出、或软件启动很慢 | 所有权保持到确认排空；SW 进程存在性不参与授权 | 真机待测 |
| L08 | 同一房间反复请求、网络丢回复 | 原票重放不插队；begin 不确定时无新 worker | 真机故障注入待测 |
| L09 | 直接 COM、单房间、主对话、出图或仿真 | 所有可触碰 SW 的入口都受同一租约约束 | 需 DS 宿主接入验收 |
| W01 | 主对话等房间 | 必须等确切名单验收且收尾；失败、失效提示处理 | 自检；真实 DSH 回合待测 |
| W02 | 软件阻塞、无新输出 | 继续等待正确的监控器事件，关闭等待不停止 CAD | 真实 DSH 后台任务待测 |
| W03 | 宿主失联或监控器持锁重启 | 冻结已领取票，不发下一把锁；确认排空才能恢复 | 自检；真实进程残留待测 |
| P01 | 同房间多个零件顺序开工 | 仅实际零件显示正在建；同房未开工不跟着亮 | 自检 |
| P02 | 中断、迟到的保存或重建 | 无保存的结束记失败；旧 generation 拒绝；重建可撤掉旧验收 | 自检；真实重建待测 |
| P03 | 外购件 BOM 合格或清单缺项 | 合格可验收；空清单、缺项及事后篡改阻断 | 自检覆盖空、合格及篡改；缺项真机待测 |
| E01 | 材料验签，物理真实运行，领域同一 run | 逐件核实三项，检查零件哈希、报告哈希及运行归属 | 合成验签替身；真实签名待测 |
| E02 | 旧凭据、路径不符、错件、审核未通过 | 保持阻塞，输出具体证据缺口 | 合成验签替身覆盖哈希；真实签名待测 |
| E03 | 台账被改、邻接不符、未解决冲突 | 旧结论失效；总装确认重新核实任务 | 合成台账审计覆盖变更；真实邻接待测 |
| E04 | 仿真关闭、仿真要求开启但没有验证器、实际仿真接入 | 分别为 NOT_REQUIRED、UNSUPPORTED、按实际验证证据判定 | 接入真实验证器后验收 |
| G01 | 原 DSH 看图、位姿、自检、总装、出图 | 原门禁均可执行；监控结果能驱动推进，禁止假报告 | 需 DS 工作流接入验收 |
| G02 | 非授权客户端、错误任务目录、重启回滚 | 未授权无法写入；旧任务状态不混用；回滚无双权威 | HTTP 鉴权自检；跨部署回滚待测 |

## 真实任务的 99% 判据

1. 先冻结统计周期、DSH 和监控器版本、SolidWorks 版本、任务范围。至少包括单件、多零件、含采购、总装、出图、恢复、失败与重建。未来要求仿真后把真实仿真用例纳入范围。入口未接通、证据不明或超过规定窗口的实际在范围任务，计入分母。
2. 用一次有独立任务 ID、独立输入与结果的真实工作单去重。同输入同计划的复跑、同一模型的多张截图、多条回归断言均不增加独立样本。故障注入和样例另存，不能填充生产任务分母。
3. 分子是全过程符合该任务所有适用预期的任务。真实工程件设计不合格而被准确拒绝，属于系统正确处理。假完成、错杀 job、未授权双持有、拿不出证据、已纳入范围但完全不支持均不得计入分子。某次锁释放后存在两个房间同时进入 SW 或错误终止真实建模 job，该版即使统计过 99% 也不通过发布验收。
4. 对图一另测延迟。用同一宿主的单调时钟记录释放确认到队首等待 job settled。参考本机接入门槛 P95 ≤ 250ms，并报告 P50、P95、最大值、丢失和超时次数。释放条件取真实 worker 排空，不能从上一次 UI 刷新时间估算。模拟宿主时延不作为真机验收结果。
5. 汇报 n、成功数 k、k/n、缺失证据数、最慢场景和 95% 单侧置信下界。若希望有统计证据表明覆盖至少 99%，零失败时至少需要 299 个有代表性且相互独立的真实任务。有失败时按精确二项分布下界计算，样本数会更大。

推荐逐条记录字段：

```text
task_id, input_fingerprint, task_class, dsh_version, sw_version, monitor_version,
scenario_ids, in_scope, expected, observed, pass, block_or_failure_reason,
lock_release_to_job_settled_ms, job_ids, evidence_paths, operator, timestamp
```
