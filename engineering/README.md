# DSH 工程模式

DSH 工程模式是一个面向机械设计的工作台。它从用户要解决的问题出发，把需求澄清、方案分析、建模、验证和交付组织到同一个项目中。既可用于单个零件，也可用于需要多方协作的机构和装配。

## 整体结构

| 部分 | 负责什么 | 怎样和下一部分衔接 |
|---|---|---|
| 主对话 | 和用户确认任务目标、使用场景、已知资料和交付要求，协调各角色的工作 | 把确认过的需求和仍待澄清的问题交给分析团队 |
| 设计分析 | 调查工况和设计依据，比较方案，细化尺寸、接口和零件要求，复核风险 | 把有依据的方案、建模约束和待补证据整理成建模输入 |
| 建模与验证 | 按模块完成零件设计和装配，检查尺寸、接口、运动及装拆条件 | 将模型、图纸和检查结果汇入同一份交付 |
| 交付 | 汇总当前版本已完成的成果、适用条件和待解决问题 | 用户可以查看模型与资料，并据此决定是否进入下一轮 |
| 工程工作台 | 展示当前流程、子代理进度和任务记录，支持故障后的模型接管 | 用户可以回到当前会话查看进展，从中断处继续处理 |

复杂任务中的分析由总计子代理组织。知识角色负责查证依据和适用范围，设计角色负责方案与参数，反驳角色独立检查失效风险、遗漏和关键假设。主对话汇总结果，并在需要现场信息或设计取舍时向用户确认。

## 工程流程

| 阶段 | 主要解决的问题 |
|---|---|
| 现场与边界 | 设备装在哪里、跟什么对接，以及它要完成什么工作 |
| 工件与工艺 | 实际处理什么对象，正常使用与异常情况有哪些 |
| 需求与验收 | 哪些指标必须达到，完成后怎样判断合格 |
| 功能与路线 | 需要哪些功能，有哪些方案，各自适用于什么条件 |
| 骨架与接口 | 如何确定载荷、运动关系、基准和各模块接口 |
| 零件与连接 | 零件怎样实现功能，连接、支撑和装拆怎样落实 |
| 整机集成 | 装配、制造、电控、维护等要求怎样在整机上配合 |

工程模式根据任务规模安排工作。简单零件可以在主对话完成建模与检查。多零件机构会先推进七阶段分析，再按模块进入建模与总装。图片重建任务会先核对可确认的尺寸与结构，再建立对应模型。

## 在 DSH 中使用

1. 新建会话时选择「工程模式」，描述你要做的对象、使用场景和期望结果。已有图纸、照片或尺寸可以一并提供。
2. 打开「工程模式」会话页签，在首页顶部查看「工程流程」。当前阶段会高亮，走完后会变暗并保留完成记录。点开阶段可以查看各步状态和待复核项。
3. 在工作台查看子代理的进度、运行日志和压缩历史。任务结束后，从设置中的交付目录查看已生成的模型、图纸和检查资料。

需要备用模型时，在「设置 → 工程模式 → 设计过程优化 → 模型自动接管」中配置顺序。当前模型遇到额度、限流等故障时，可由备用模型接手，也可以开启接手后的自动续跑。

工程模式支持 SolidWorks 建模和 AutoCAD 图纸工作，可按任务接入 Webots 仿真。交付内容会随任务范围和本机配置而定。
