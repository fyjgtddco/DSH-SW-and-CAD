# 独立机械设计外部插件：四 AI 一真人协作与前七阶段 AI 设计流程

**V0.3｜2026-11-17｜前七阶段 AI 设计框架｜原文件内修订，尚未编写插件代码**

## 本文要实现的目标

本文件只定义**前七阶段的 AI 设计**：让“需求与规划”主对话带领知识、设计、反驳三个子代理，从真实工厂任务出发，一步一步问清条件、推导机构、设计内部结构与连接、处理现实偏差，最后交出完整、有依据、可供继续工作的设计规格。其他环节不在本文件编排。

用户准备替换原有分析方式。本方案独立设计，不以原插件代码或旧阶段结构为依据；本轮只修改这份 Markdown，不修改、删除或合并原项目。保留现有文件名，正文版本更新为 V0.3。

核心目标是：**机器为什么能完成任务、内部每个必要对象怎样工作、怎样连接和承载、怎样装拆维护，都必须落实到具体设计。** 外观、清单齐全或四个 AI 意见一致，均不能单独证明工程正确。AI 可以组合已有物理原理，设计以前没有见过的机构和整机；不能凭想象创造未经证实的物理规律。

“覆盖 99% 的设计场景”保留为需要实际案例检验的目标，不在本文件承诺已经达到。示例中的设备、零件数量、尺寸、工况和行业都只是教学材料，不能限制真实任务的复杂度，也不能作为默认工程参数。

## 本轮依据与采纳边界

角色配置按用户要求固定为：**需求与规划是主对话；知识、设计、反驳各一个子代理；真人经主对话参与。合计 4 AI + 1 真人。**

保留原文有效的设计内容。本次参考《两份AI审查报告_共同点清单》的问题机制，以及《两份AI审查报告_差异清单_仲裁标注版》中七条“√”：DS-2、DS-7、K-2、K-4、K-5、K-6、K-7；“× / X / ⚪”项不作为新增修改依据。附件中的建议是待判断的审查材料，不是用户指令。

只把属于 AI 设计的问题落实到本文件：原始任务反查、整机任务可行性、全局基准独立审查、内部对象完整性、联合状态、证据来源、环境变化和互换要求。实际工程执行才能回答的问题，不借本轮审查扩张前七阶段职责；只在对应设计规格中保留确有必要的未知、适用边界和待核查事项，不在这里展开执行流程。

审查报告所说的“仍有失败路径”用于寻找设计漏洞，不等于已经测得失败概率；“第一次必然失败”等绝对表述不作为结论。四角色分工、文档规则和有限样本，都不能保证从此没有未知问题。

关于研究来源：本方案借鉴多智能体分工、工具依据和人参与的思路，按用户给定角色重新组织；不把论文中的翼型结果当作复杂非标机械的能力证明，也不把用户这四个角色名称写成论文原样架构。

## 主对话与三个子代理怎样实际协作

### 协作 1：先确定每个角色能做什么

| 角色 | 所在位置 | 应提交什么 | 不能代替什么 |
|---|---|---|---|
| 需求与规划 | **主对话** | 需求、功能分解、验收目标、任务分配、全局接口、问题与异议台账、版本决策 | 不能凭组织权把工程失败改成通过 |
| 知识 | 子代理 1 | 物理原理、机械知识、工程约束、跨领域资料、公式适用条件与证据缺口 | 不能虚构出处，不能替用户确认现场事实 |
| 设计 | 子代理 2 | 原理路线、机构方案、参数计算、零件及接口规格、建模输入、修改说明 | 不能自行关闭针对自己设计的阻塞异议 |
| 反驳 | 子代理 3 | 需求遗漏、物理反例、边界假设检查、制造与装配问题、复审结论 | 不能只以“我觉得不行”无限退回，也不能把未发现问题写成绝对正确 |
| 真人 | 通过主对话参与 | 工厂事实、业务偏好、资料协调、范围和权限内的决定 | 用户签字不自动变成计算、试验或专业判断证据 |

工具、数据库和检查程序是基础设施，不计为第五个 AI。三个子代理分别保留独立会话；默认不再各自无限分叉出新代理。复杂模块作为有输入输出的小任务分配给现有角色，是否扩展队伍留待明确需求。

### 协作 2：先审真实任务，再让设计方案主导讨论

1. 主对话保存用户原话、资料及来源，区分观察、测量、回忆、估计和偏好。
2. 知识子代理先给出相关物理约束、常见盲点及证据获取办法。
3. 反驳子代理先阅读原始需求、现场材料和当前事实表，独立列出“可能没有被问到的核心任务”，此时不先读取设计者的结论摘要。
4. 主对话合并重复问题，优先向真人询问会改变路线或验收对象的内容；子代理只提交问题请求，不能代答。
5. 形成首轮需求基线后，设计子代理开始生成与计算候选方案。基线仍可通过正式变更修改。

这并不保证反驳一定发现漏项；它减少由同一份设计摘要限定审查范围的问题。反驳可申请原始资料、独立测量或另一种计算路径，不能只重述知识代理的结论。

### 协作 3：每轮按同一条回路执行

```text
真人 ↔ 需求与规划主对话
          │ 任务、当前基线、缺口和允许范围
          ↓
       知识子代理 → 可追溯知识、适用边界和待取证问题
          ↓ 由主对话校验版本、组织交接
       设计子代理 → 候选方案、计算、零件与接口规格
          ↓ 同时提供原始资料和工具证据
       反驳子代理 → 通过本轮审查 / 有条件探索 / 阻塞异议
          ↓
       主对话分类并分派
          ├─ 事实或目标问题 → 真人 / 资料获取 → 更新需求
          ├─ 知识或模型问题 → 知识子代理 → 重新取证
          ├─ 设计问题 → 设计子代理 → 修改与重新计算
          └─ 复审无当前阻塞 → 当前版本进入下一步
```

日常工作可以并行准备，但设计不得使用未确认版本；任何关键变更使相关反驳结论和放行状态过期。主对话负责追踪，不重新代演三个角色的工作。

### 协作 4：每份异议必须能行动、能复审

异议记录至少含：编号、对象及版本、违背的要求或待检验假设、具体失效机制、证据或反例、影响的动作、应补的数据、接收角色和关闭判据。

例如“安装板不可靠”不够。应写：“在当前偏心工况下，连接计算把接触面视为完全绑定，但实际接头可能分离；需要复核接触、预紧范围和安装板撬曲。在依据补齐前，该连接不能作为已完成的详细设计提交。”

| 异议类别 | 处理方式 |
|---|---|
| 证据已说明违反硬要求 | 阻塞受影响放行，修改后以新证据复审 |
| 关键假设缺证、结果可能改变 | 保持未知，安排取证；可继续无依赖工作 |
| 已证明限定条件下可接受 | 保存条件和证据，不扩大适用范围 |
| 偏好或不同可行路线 | 展示取舍，由主对话在授权内决定或交真人选择 |
| 缺少依据的反对 | 要求反驳补充可检验机制；记录理由后可判为无依据异议，不能把真实缺证误归这一类 |

设计代理提交“修改了什么、基于什么证据、影响了哪些对象”，反驳代理再判定关闭。主对话只有在关闭条件满足时提交新状态；不能投票、换一个听话的反驳角色或用用户签字消除物理缺口。

同一争议若完整往返两轮仍无新证据，默认停止重复辩论，转向明确的测量、计算、试验或具备能力的专业审查；两轮是可配置的工作效率规则，不是自动放行阈值。缺资源时交付带阻塞项的探索结果。

### 协作 5：只判断本轮 AI 设计做到哪一步

| 设计状态 | 可以继续什么 | 需要保留的限制 |
|---|---|---|
| 探索中 | 调研、澄清、比较路线、数量级计算和草案 | 关键原理或事实可能尚未确定 |
| 局部设计可继续 | 对输入充分的模块细化零件和接口 | 不得冻结仍依赖未知事实的接口与尺寸 |
| 待设计复审 | 设计提交完整规格及自己的检查依据 | 作者提交不等于反驳已接受 |
| 本轮设计规格可提交 | 反驳确认本轮设计阻塞已关闭，原始任务和内部细节有对应实现 | 只表示该范围的设计规格具备交接条件，不表示现实机器已被证明可用 |
| 受影响部分待补证或待重设计 | 保存已有成果，继续独立工作 | 不用“已记录未知”替代问题解决 |

判断对象是具体模块、接口和版本，不能把局部可以继续写成整机已完成。现阶段尚不具备条件的核查不伪造结果，也不能成为“必须先造出整机才能开始设计”的循环依赖。如果缺失事实足以推翻任务原理、关键载荷或主要接口，相关内容保留为探索草案。

是否具备交接条件取决于内容和证据，不能仅按阶段编号打勾。

### 协作 6：每次交接保留为什么，而不仅是结果

主对话发出的任务包必须包含：原始需求与事实来源、基线版本、本轮目标、不可擅改项、候选方案及淘汰原因、参数范围与敏感性、未决异议、验证等级、预期产物和禁止的放行。

接收代理返回已读版本和缺口。摘要需要链接到原始证据及具体位置；接收方找不到来源就不能把摘要当作已验证事实。会话恢复或角色替换时继承这些记录，开放异议不能因换会话而消失。

主对话对整机可用性拥有统筹责任；知识负责来源和适用性，设计负责实现与全局兼容，反驳负责审查结论。涉及实物和专业认可时，另记录现实中的执行人与工程责任人，AI 职责不能代替人的实际能力。

## 先看前七阶段怎样走

```text
真人描述生产问题 ↔ 需求与规划主对话
    ↓
阶段一：看懂真实现场，确定机器边界和原始任务
    ↓
阶段二：看懂工件与工艺，查清变化、异常和未知
    ↓
阶段三：把目标变成要求，确定判据和整机预算
    ↓
阶段四：拆功能、比较原理，检查完整任务的可行性
    ↓
阶段五：建立内部骨架、载荷路径、运动、基准和接口
    ↓
阶段六：逐件落实必要零件、支撑、连接、螺钉和装拆细节
    ↓
阶段七：整合各专业设计 → 独立反驳 → 修改复审 → 输出设计规格
```

每一阶段都执行“知识给依据 → 设计给方案 → 反驳找具体问题 → 主对话组织解决”的小循环。任一阶段发现前提错误，立即返回受影响位置，不等到阶段七才检查。

复杂设备按“整机 → 子系统 → 工位或机构 → 零件 → 连接与实例”逐层展开；每层仍用同样的七阶段问题检查输入、输出与接口。不是给每层再开一套 AI，也不是各模块各自完成便算整机完成。主对话始终维护共享空间、载荷、节拍、能源、基准和异常传播关系。

下文按“先拿什么 → AI 做什么 → 缺什么才问用户 → 答完怎样改设计 → 交出什么 → 满足什么才继续”展开。正文中的制造、装配、维护与环境内容，均是现在要考虑的**设计约束和可执行性推演**，不表示本轮去执行这些工作。

## 开始前：先规定 AI 工作时的八条规则

### 规则一：不知道的地方，留下明确的空缺与下一步

AI 不知道材料、接触摩擦、工件强度或工艺力时，应记录未知量。它可以给出用于探索的假设范围，但不能把假设写成用户已确认的事实。

每个未知量记录：影响哪个决定、由谁补充、怎样获得、在补齐之前哪些工作允许继续。例如不知道压装力，可以继续研究人工上料位置，但不能冻结压装机构和受力框架。

### 规则二：先看输入到输出，再设计形状

机器必须改变某些东西：工件位置、形态、连接状态、温度、清洁度或质量信息。AI 先写清变化过程和成功条件，再选机构，随后确定零件和外形。

### 规则三：每个“已经完成”都有具体对象和版本

“完成”必须说明是哪一版需求、哪条原理路线、哪个机构或哪份设计规格完成了什么审查。概念草案可以保留探索假设，拟提交的详细设计不能把足以推翻结构或接口的未知藏起来。

### 规则四：问题、计算、设计规格和已有实测资料使用一致的参数定义

例如用户确认“最大工件质量 8 kg”，不能让运动计算按 5 kg、夹具按 10 kg，而报告写 8 kg。不同工况可以有不同数值，但各自来源、含义和适用范围必须明确。

### 规则五：每个零件和每个连接都要有理由

零件要有功能、接口、安装方式和检查方法。连接要有位置、受力、定位、紧固或传力方式，以及可实现的装拆过程。不能用一个漂亮实体替代缺失的轴承、连接、密封、紧固件或工艺空间。

### 规则六：真实世界的偏差要进入设计输入

尺寸散差、材料批次、油污、磨损、温度变化、气压波动、断电、误操作、工具伸不进去、备件买不到，都可能改变设计是否可用。不能只检查理想模型的一个姿态。

### 规则七：AI 的解释是线索，证据才决定放行

解释清楚不等于算对、制造得出或工作可靠。需要可追溯的资料、计算结果、检查记录、试验或责任人确认。生成式 AI 存在自信表达错误内容的风险，因此不能把自评作为唯一验收依据。[依据：NIST 生成式 AI 风险资料](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)

### 规则八：不把安全、采购和制造授权混在“自主设计”里

AI 可以在已授权的边界内分析、比选和修改设计。采购下单、加工制造、接管现场设备或投产，需要相应责任人授权。用户“你决定”可以授权设计权衡，不能替代未知事实或工程验证。

## 流程一：看懂真实现场，确定机器边界

**本阶段分工：** 主对话问现场与边界；知识提出取证方向；设计仅做任务可视化和探索；反驳查原始需求遗漏。

### 1.1 第一步，先让用户讲一件产品的经历

**AI 开口这样问：**

> 请从一件产品进入工位开始讲：它进来时是什么状态，人现在依次做什么，最后怎样才算做好？先按实际操作讲，不需要告诉我机器应该长什么样。

**收到答案后，依次做：**

1. 保存用户原话，不立刻改成自己的理解。
2. 把过程分成输入、动作、输出三列。
3. 标出哪些动作由人完成，哪些由现有设备完成。
4. 标出用户想让新机器接管的动作。
5. 用几句话复述边界，只对有歧义、影响范围的地方继续问。

**例子：** 用户说“拿壳体、装密封圈、压衬套、拧螺钉、测漏、放到合格箱”。此时得到的是工艺草案，不能直接决定用转盘、机器人或某种气缸。

### 1.2 第二步，先确定问题为什么值得解决

按实际需要逐项问：

- 当前最主要的问题是人太累、产量不够、良率低、危险、招不到人，还是要适配新产品？
- 什么改善最重要？如果成本、节拍和通用性互相冲突，优先保住哪一项？
- 是改造现有线，还是做完全独立的机器？

AI 把回答写成“首要目标、次要目标、不可牺牲项”。若用户说“全部都要”，AI 先记录；后面出现真实冲突时再让用户选择，不预先制造取舍。

### 1.3 第三步，确定现场边界

按当前方案相关性逐步收集，而不是一次抛出整张问卷：

| 要查什么 | 为什么要查 | 用户不知道时的下一步 |
|---|---|---|
| 可用区域、净高、进出料方向 | 决定整机布局与物流 | 现场测量并标明墙、柱、门和通道 |
| 楼板或地面条件、锚固限制 | 决定支撑和安装边界 | 向厂务或结构责任人索取资料 |
| 门洞、运输通道、吊装条件 | 判断整机或模块能否运进去 | 测量转弯、门洞和吊点通路 |
| 电源、气源、真空、冷却等 | 决定执行和工艺方案 | 由相关人员确认可用能力与波动范围 |
| 温湿度、粉尘、油雾、冲洗与腐蚀 | 决定材料、防护与维护 | 查现场记录，必要时测量 |
| 人员活动、补料、清洁和检修方式 | 决定可达性、隔离和操作界面 | 观察典型操作，不只看空车间照片 |
| 上下游节拍、缓存与通讯 | 防止单机能跑但整线堵死 | 收集正常、缺料、满料和停机情形 |
| 采购、加工和维修能力 | 决定方案能否落地 | 列出现有供应链、设备和人员能力 |

### 1.4 第四步，确定本轮要设计到什么深度

主对话确认本轮对象是整机、改造模块、单机构还是工装，明确要给概念候选、机构方案还是详细零件与连接规格。不要把“做一台机器”直接理解成只画一个外壳。

若用户要求完整详细设计，内部承载、导向、定位、连接、驱动、供能、检测和维护对象均须进入设计范围；采购模块可以按经核实的接口作为一个组件，但不能把自制的未知内部机构藏成“黑盒模块”。

### 1.5 第五步，建立现场版本

产出一张《现场与任务边界表》，记录资料来源、采集时间、适用产品和仍未确认的内容。

### 1.6 四角色一起检查现场叙述遗漏了什么

1. **主对话建立多方事实表。** 同一位真人可以代为协调操作、工艺、质量、维修、厂务和管理人员的资料，但每条事实保留实际来源；意见不同不拼成一条假共识。没有明确提供方的环境事实，由主对话分配采集任务，不能因无人负责就消失。
2. **知识列出现场历史与观察点。** 查旧设备故障、改造、地面与安装变化、遗留管线和典型不良；这些是待查项目，不凭现场照片臆断历史。
3. **主对话核对叙述与行为。** 在现场授权范围内收集正常、换型、卡料处理、清洁及不同班次的观察记录，确认人工扶持、擦拭、挑件、修边等隐性动作。无法观察时标明证据缺口，不把作业指导书等同真实操作。
4. **反驳检查数字来源。** 对“从不装反”“应该一小时够用”等说法追问依据、时间范围和记录。现场估计先标估计；不把真人现场给出的数字立即升级成统计事实，也不凭空给其编造可信度百分比。
5. **设计提出整机任务演示。** 用工件完整经历、操作脚本或低成本工艺演示确认是否解决实际问题，包含可能影响使用的噪声、热、清洁和操作负担。这里的使用体验确认与专业工程判定分别记录。
6. **反驳从原始场景反查需求。** 不先只读需求表；列出“即使表内指标全过，机器仍可能不能用”的具体反例。主对话把成立的反例变成需求或待取证任务。

**四个角色都可能理解错同一句话。** 主对话不能只问“需求表这样写对吗”，还应让真人描述一件合格产品怎样从输入变成输出、一件失败品具体差在哪里，并请求现有样品、操作记录或工艺资料作对照。反驳检查“同一个词是否掩盖不同任务”，例如清洁可能包含去除附着物、带走废物和保护基材；应按真实对象确认，不照抄例子。

**本轮产物：** 现场证据表、干系人冲突表、原话到事实的核对记录、隐性操作清单和整机任务脚本。没有外部事实支撑时，可继续探索，不宣布真实场景已经覆盖。

**可以继续的条件：** 已知道输入和输出、新机器负责的范围、主要目标，以及目前缺少的现场事实。允许带着明确未知量进入调研；对未知量有依赖的决策暂时不冻结。

## 流程二：看懂工件与工艺，查清正常和异常情况

**本阶段分工：** 主对话组织真实工件和工艺资料；知识识别物理属性与测量办法；设计形成工艺候选；反驳查分布、尾部和异常传播。

### 2.1 第一步，把“产品”拆成真实零件和状态

1. 为每种工件建立身份：名称、版本、规格、材料及来源。
2. 收集外形尺寸和公差、重量范围、重心或质量分布、表面状态。
3. 标记允许接触面、外观禁触面、装配基准和关键功能面。
4. 记录刚度、易碎性、可变形性、磁性、渗透性、带油带水等与工艺相关的特性。
5. 记录来料姿态：整齐托盘、散料、缠绕、堆叠、混料、方向随机。
6. 记录变型：同一工件是否有左右件、不同尺寸、不同材质或不同供应商。

**AI 不应只问“有没有图纸”。** 没有图纸时，继续问是否有样件、现场照片、人工操作记录或产品负责人；说明这些材料分别能回答什么，仍缺哪些测量。

### 2.2 第二步，跟着人工工艺拆动作

对每个动作依次问：

> 操作者怎么拿？靠什么找方向？什么位置要对准？靠感觉判断什么？做坏时通常怎样？

随后把隐性经验改写成可观察要求：

- “拧到差不多” → 需要确定紧固策略、合格判据及来源。
- “压进去就行” → 需要确定压入终点、力位移特征和允许损伤。
- “摸一下知道有没有装好” → 需要找可测量的高度、间隙、位移或信号。
- “卡了就晃一下” → 需要分析卡料原因、允许的恢复动作及退出条件。

人的经验有价值；AI 要把它转成工艺条件，不能直接删除。

### 2.3 第三步，列出每道工艺的窗口

每个工序都填写：进入条件、执行动作、关键过程量、允许范围、结束条件、合格判据和失败后去向。

例如压装工序需要考虑对中、支撑、导向、速度、力位移、终点与工件损伤；测漏工序要考虑密封夹具、测试介质、温度、稳定时间、背景泄漏和判定方法。具体数值必须来自工艺资料或试验。

### 2.4 第四步，把异常单独过一遍

按以下顺序检查，不适用项也要写理由：

1. 空料、少料、双料、反料、错料、混料。
2. 毛刺、变形、油污、异物、批次差异。
3. 工件没拿稳、没到位、传感器误判。
4. 工具磨损、卡住、折断、夹具松动。
5. 工艺超力、超温、超时、泄漏、尺寸不合格。
6. 半成品停在机器内，停电后再次启动。
7. 下游满料、上游持续送料、废料箱满。
8. 操作者清洁、补料、调整或打开维护位置。

对于每种异常，AI 要说出“怎么发现、怎样进入适当状态、工件如何处置、谁能恢复、恢复前检查什么”。不能只写“增加报警”。

### 2.5 第五步，把决定路线的工艺未知说具体

若某个未知会决定方案能否成立，先查已有工艺数据、样件记录与可靠资料。例如软密封圈能否自动拉伸并装入曲槽、表面带油的零件能否稳定吸取、薄壁壳体能否承受所需夹紧力。

没有依据时，主对话把缺口写成“缺什么量、针对什么对象和状态、需要什么来源、会改变哪些设计”的具体资料请求。知识给出可行的取证建议；本文件不展开实际试验执行。相关路线保持探索，独立工作可以继续。

### 2.6 把来料区间改成有来源的分布与变化过程

1. **知识给出属性清单和测量办法。** 除几何外，识别相关材料状态、热处理、硬度、柔性材料的时间与环境行为、表面油水和污染条件；只在与所选机理有关时要求相应证据。
2. **主对话组织有记录的取样。** 标记供应商、批次、模具或工艺来源、班次及抽样方式，纳入正常来料与异常退件；不能由设计者只挑规整样件。不能取得代表性样本时，保留限制和补样任务。
3. **设计把变化放入工艺窗口。** 用样本和可解释边界分析定位、夹持、压装、吸附等对属性变化的敏感性。不能把所有分布假定为均匀或正态，也不能用一个“典型摩擦系数”覆盖未知表面状态。
4. **反驳检查时间与故障传播。** 同一窗口在冷机、热机、磨损、污染和不同批次下是否仍成立？连续制造不良时多久能发现，检测延迟期间有多少在制品可能受影响？
5. **主对话分配不良隔离任务。** 设计给出检测点、停止条件、受影响批次追溯和复检规则；反驳检查不良品回流、重复检测和漏检的路径。
6. **保留未知异常入口。** 每次新的卡料、表面状态或材料行为进入新场景，不强行归入已有大类然后宣称已覆盖；更新相应试验与设计边界。

**本轮产物：** 带批次与时间信息的工件属性表、工艺窗口版本、不良传播与隔离图、未知异常台账。

**可以继续的条件：** 正常工艺已描述，关键异常已列出，工艺未知已对应具体资料请求。若原理仍无证据，可以研究候选方案，但不能把依赖它的结构当作已定型设计。

## 流程三：把目标变成可验证的要求，决定怎样验收

**本阶段分工：** 主对话制定需求和验收；知识校核指标依据；设计分配系统预算；反驳检查需求是否忠于真实任务。

### 3.1 第一步，把形容词翻译成可检查的目标

| 用户说法 | AI 接下来怎样问 | 转成什么要求 |
|---|---|---|
| 要快 | 每小时多少合格件？按什么运行时段计？停机和换型算不算？ | 合格产出及统计口径 |
| 要准 | 哪个位置或尺寸？相对哪个基准？允许变化多少？ | 具体精度、基准与检测条件 |
| 要稳 | 最怕哪种停机或不良？什么时段和条件下考核？ | 可靠性、良率和恢复目标 |
| 要通用 | 必须支持哪些产品？未来变化有多大？换型多久？ | 产品族和换型范围 |
| 要省钱 | 预算含哪些费用？允许哪些性能取舍？ | 预算边界和比较原则 |
| 好维修 | 谁维修？常用工具是什么？多久必须恢复？ | 可达性、备件和维修要求 |

### 3.2 第二步，先写一条完整要求，再按同样方式写下一条

一条要求至少包含：

1. **对象：** 是整机、工位、夹具还是某个连接？
2. **条件：** 哪种产品、环境、工况和运行方式？
3. **目标：** 数值、范围或可明确判定的状态。
4. **依据：** 用户、产品规范、现场测量、工程推导还是假设？
5. **验证方法：** 看文件、测量、计算、试验还是现场运行？
6. **责任人与状态：** 谁确认，当前是否有证据？

例子：“在指定产品组合、来料条件和统计时段下，每小时输出不少于约定数量的合格产品；按现场验收记录计算。”数量、产品组合和时段必须由实际任务确定，不能留模糊定义却写“需求已冻结”。

### 3.3 第三步，建立完整工况表

至少判断以下工况是否适用：正常运行、最大载荷、最大偏心、加减速、紧急停止、堵转或卡料、换型、人工调整、清洁维护、断能恢复、运输吊装和长期磨损。

不能简单把所有最大值叠加成一个不可能同时发生的工况，也不能漏掉确实可能同时发生的组合。每种组合说明产生条件。

### 3.4 第四步，明确现实偏差怎么覆盖

每个关键参数分清：标称值、允许范围、批次差异、测量不确定度和使用中变化。

对敏感参数做范围分析。如果夹紧力稍变就伤件，或来料尺寸稍变就卡住，说明方案需要提高适应能力，不能只挑一个理想样件过关。

### 3.5 第五步，区分任务成功判据与当前设计审查判据

| 要检查的内容 | 当前设计应给出什么 | 不能省略什么 |
|---|---|---|
| 任务是否定义清楚 | 输入、输出、工艺、合格判据与适用范围 | 原始生产目的及关键辅助动作 |
| 路线是否值得细化 | 完整任务路径、主要预算、原理依据与敏感假设 | 动作之间的耦合和足以推翻路线的未知 |
| 内部是否达到约定设计深度 | 必要零件、载荷、基准、连接、孔位与装拆定义 | 不能只用外形或清单代替内部实现 |
| 整机规格是否可提交 | 原始任务反查、接口一致性、独立复审和剩余缺口 | 局部通过不等于整机完成；设计审查不能冒充实测 |

任务成功判据是设计要实现的目标；当前设计审查判断实现路径、定义和依据是否足够。二者要对应，不能因尚未执行现实工作而编造目标已经达成。

### 3.6 第六步，记录冲突和权衡

如果占地、节拍、预算和产品兼容要求不能同时满足，AI 应给出具体矛盾和可选调整：增加空间、增加工位、降低产量、缩小产品范围或改变工艺。先用数据说明代价，再让用户选择需要他决定的部分。

### 3.7 对目标本身做反驳，并定义寿命与整机预算

1. **主对话保留真实意图。** 对“工人愿意用、少打扰维修、容易清洁”等目标，同时保留原话、具体使用场景和可观察判据；量化指标仅代表其中可量化部分，不用换型时间一个数代替全部体验。
2. **反驳审查验收对象。** 把真实工艺任务与验收表逐项对照，检查是否只测行程、速度和尺寸，却漏掉真正的装配质量或生产目的。用户对需求的确认与工程有效性分别判定。
3. **主对话固定产出口径。** 分别记录理想周期、有效运行产出和包含换型、补料、停机、不良的计划期合格产出；明确时间分母、产品组合、排除时间和原始计数。不用短时平均值替代年度生产目标。
4. **明确寿命对象。** 给整机、关键结构、运动副、线缆和易损件定义运行小时、循环或换型次数及环境、维护前提；同时定义允许的精度退化、失效判据和验证等级。没有载荷谱时记录缺口与采集方案，不把猜出的谱算成实际寿命。
5. **设计分配整机预算。** 将允许变形、定位误差、热漂移、节拍、能源、质量和成本分配到子系统，保留系统余量。每一预算有总上限、责任对象和依据，不让多个模块各自占用同一份裕量。
6. **反驳核对分配和风险分级。** 强度未超限不能代替精度和刚度目标；各模块合格仍要检查整机预算是否超限。检查深度依据功能、失效后果和实际受力决定。
7. **需求变化走版本化回路。** 用户看见方案后增加要求时，主对话说明影响、更新范围和验收基线；设计与知识重做受影响部分，反驳复审。不得沿用旧版本签字和旧证据。

**本轮产物：** 真实任务到验收的对照、体验场景、寿命目标、整机预算及需求变更记录。

### 3.8 把原始任务和维修互换要求固定下来

1. **主对话把用户原始任务拆成可追溯动作。** 每项保留原话位置、处理对象、输入状态、动作、合格输出、适用范围和不可遗漏的条件。例如“自动装配”不能只剩搬运，必须说明实际完成哪种装配和怎样区分合格品。
2. **设计写对应实现。** 把动作映射到功能、工艺、机构和必要辅助条件；一个动作可以由多个机构联合完成，一个机构也可以服务多个动作。不能为了方便列表把真实耦合删掉。
3. **主对话单独询问互换预期。** 对维修件、换型件和采购接口，问清允许的来源与配置、是否要求规定范围内任意合格件直接替换、是否允许选配或调整、允许调整什么及最大停机代价。只有答案会改变设计时才问，不逐颗询问螺钉。
4. **设计把答案变成接口要求。** 用户要求直接互换时，不能自行改成配作、挑件或现场扩孔；若当前能力达不到，提出结构、精度、采购范围或成本的可选变化，由主对话处理要求冲突。
5. **反驳保留对照基线。** 原始任务或互换目标要改变，必须有明确的需求变更记录。方案自己少做了一项，不能反过来自动删掉原要求。

产物是“原始动作 → 功能 → 实现对象 → 成功判据”的对照及互换边界。阶段七必须从原始动作重新反查一次，不能仅检查设计者后来保留下来的功能表。

**可以继续的条件：** 关键要求有来源、条件和验证办法；不可调的硬约束与可权衡偏好已经分开；当前目标的矛盾已解决或明确转为待决项。

## 流程四：拆功能、比较路线，检查完整任务的可行性

**本阶段分工：** 主对话控制范围和取证次序；知识提供原理与适用边界；设计给候选及计算；反驳查共同错误前提和整机反例。

### 4.1 第一步，把整机目标拆成动词

先写“供料、识别、定向、分离、搬运、定位、夹紧、加工或装配、检测、分流、排废、恢复”等动作。

暂时不要把“机器人”“转盘”“气缸”当作功能。它们是可能的实现办法。AI 先确认真正需要做的事，才不会因为熟悉某个零件而强行往机器里塞。

### 4.2 第二步，给每个功能补齐输入和输出

例如“定位”不能只有两个字。要写成：

> 接收方向和尺寸处于约定范围的壳体，把关键工艺面放到约定基准附近，限制不需要的运动，同时不压伤禁触面；向后续工位提供到位状态。

随后检查：输入从哪里来，输出交给谁，条件不成立怎么办。把功能连成物料流、能量流和信息流三条线。

### 4.3 第三步，检查辅助功能有没有漏掉

依次追问：

1. 谁保持工件稳定？
2. 谁检测它已经稳定？
3. 谁给机构供能？
4. 谁承受动作产生的反力？
5. 谁把废料、热量、油液或粉尘带走？
6. 谁防止人员接触危险区域？
7. 谁使机器能复位、换型和维修？

这些问题会导出真正必要的内部结构。只列主动作，往往会漏掉支撑、导向、检测、管线和维护设施。

### 4.4 第四步，为关键功能提出不同原理

不是把同一种机构换三个品牌，而是改变实现原理。例如定位可以考虑可重复定位托盘、工件直接定位、视觉配合可调夹具；搬运可以比较直线移载、机器人、转位机构。

先按物理机制和关键假设选择有实质差异的候选路线，不以路线数量作为多样性的证明。若当前只能找到一种合理路线，记录搜索范围和淘汰依据，由反驳检查共同前提和遗漏方向；数量不能代替证据。

### 4.5 第五步，先淘汰违反硬约束的路线

逐条检查产品禁触面、工艺需求、空间、能量、人员安全、生产环境及供应条件。违反硬约束的方案直接淘汰，不能靠在“美观”“先进”上打高分抵消。

对于依赖未知工艺的方案，标记“待原理试验”，不能当成已证实的最佳路线。

### 4.6 第六步，再比较剩下路线的现实代价

比较节拍、稳定性、换型、控制复杂度、维护、占地、采购周期和全生命周期成本。写出来源和范围，不凭空填出精确报价或可靠性百分比。

如果两条路线的优劣完全取决于一个未知量，先解决那个未知量。例如能否共用定位基准，可能比提前计算整机螺钉数量更重要。

### 4.7 第七步，用简化计算和已有事实反驳方案

AI 要主动问：“哪条事实如果成立，这个方案就做不成？”

- 若来料姿态超出可识别范围，供料路线是否失败？
- 若装配力偏大，工件是否先损坏？
- 若关键工序天然耗时很长，单工位是否永远达不到产量？
- 若一人无法安全补料，所谓全自动是否依赖不可行的人工动作？

先用低成本计算和已有事实寻找否定方案的依据，再投入大量细节设计。缺少关键事实时提出具体资料请求，不用继续增加零件掩盖原理缺口。

### 4.8 第八步，输出本轮选择

交出《功能与路线表》：功能、候选方案、淘汰原因、选中原因、依据、剩余未知及对当前设计的影响。

### 4.9 比较路线时，先检查它们是否依赖同一个错误前提

1. 知识把每条路线拆成关键物理假设，例如接触方式、摩擦条件、可用能量、可见性或工艺窗口。
2. 设计制作“路线 × 关键假设”表，标出多条路线共同依赖的前提。换品牌、换外形或同一传力方式的变体不自动算原理独立。
3. 反驳选取能同时推翻多条路线的假设，提出低成本取证或反例；必要时要求设计寻找不同物理路径，而不是再增加同源方案数量。
4. 主对话安排有价值的取证，保留有限候选集合与未探索范围。缺少可靠分布时不编造风险概率或最优排名。
5. 反驳从整机任务审查方案：局部能动、单个动作成功，不等于完整生产任务能连续达标。

**本轮产物：** 路线假设差异表、共同脆弱点、反例结果和选择理由。无法证明所有路线已探索，报告必须如实标明搜索边界。

### 4.10 在大量细化零件前，把完整任务走通一遍

**第一步：连成一个完整任务周期。** 设计从输入进入机器写到合格输出离开，再写机器怎样恢复到可以处理下一件的状态。连续设备要说明连续流怎样维持，批处理设备要说明批次切换；不能强套单件循环。

**第二步：检查动作之间会不会互相破坏。** 主动列出工艺反力与支承、移动与拖曳、夹持与变形、处理与排废、检测与可见性、并发动作与能源等耦合。逐项问“这个动作成功以后，下一动作还成立吗？”“两个动作一起做时，原来的假设还成立吗？”

**第三步：做足以淘汰错误路线的早期估算。** 用现有证据检查整体力与功率、节拍与缓冲、物料和废物去向、空间和可达范围、误差预算及异常恢复。明确输入范围、量纲、假设和敏感项；不能把局部原理小试直接外推成整机连续能力。

**第四步：让反驳挑一条最可能让任务中断的路径。** 从原始任务选择挑战条件，指出断在哪里、为什么断、缺什么依据。若改变一个合理输入就使路线无法完成主要任务，先补事实或比较别的路线，再投入大量详细设计。

**第五步：只在当前深度作结论。** 没有发现原理矛盾、主要资源预算可解释、关键假设有依据，才把路线作为详细设计基线。仍可能推翻路线的未知保留探索状态；无需在此制造出整机，也不能因为已画很多零件而拒绝推翻路线。

**可以继续的条件：** 选中路线满足已知硬约束，关键原理具备当前设计深度所需证据；仍未知的部分有隔离边界和补证任务。不得以“AI 更喜欢这个”作为唯一理由。

## 流程五：搭内部骨架，确定载荷、运动、基准和接口

**本阶段分工：** 主对话统筹全局接口；知识核对物理模型；设计建立骨架、基准与运动；反驳查真实传力、支承和全局冲突。

这一流程先画清“里面怎么工作、力怎么传”，随后再把外形围起来。外观空间、操作界面与内部结构可以反复协调。

### 5.1 第一步，画出完整动作链

以压装工位为教学例子：

```text
驱动源 → 传动或执行机构 → 压头 → 被装配零件
                                  ↓
                         工件支撑与定位夹具
                                  ↓
                         底座与受力框架
                                  ↓
                 执行机构安装位置形成局部反力闭环
```

图只是关系，不规定必须用哪种框架。AI 要根据实际结构标明各连接承受的力、力矩和运动；外部不平衡载荷如何传至支脚、地面或其他支承也要说明。

### 5.2 第二步，逐个问“这个力最后去了哪里”

对每个驱动、工艺接触、重力和惯性作用：

1. 标出力或力矩的作用位置、方向及工况。
2. 找到直接承受它的零件。
3. 沿连接一直追到反力闭合或外部支承。
4. 检查每一个中间件和连接是否真的存在。
5. 检查偏心是否产生额外弯矩、扭矩和倾覆趋势。
6. 区分局部工艺力闭环和整机对地载荷，避免重复或漏算。

若压头很强，但底下只有薄罩板，流程必须在这里停住并重新设计支撑。

### 5.3 第三步，明确谁是承重件、谁是定位件、谁只是外罩

对每个构件写功能类别：承载、传力、导向、定位、连接、防护、密封、检测安装或外观。

**承重柱的判断依据是受力，不是形状。** 一个竖着的圆柱可能只是导向轴；一个横向板件可能承担主要弯曲。AI 必须回答：

1. 柱或框架连接了哪两个受力节点？
2. 主要承受轴压、轴拉、弯曲、扭转，还是组合载荷？
3. 长细、约束与偏心会不会导致失稳？
4. 刚度不足会不会影响工艺精度？
5. 底端、顶端连接怎样传递这些载荷？
6. 运输吊装、停机和维修时受力是否改变？

不得因为名字叫“承重柱”就默认通过，也不能让防护罩无意中承担未经计算的结构载荷。

### 5.4 第四步，明确每个机构该有几个自由度

先说“它应该怎样动”，再说“什么让它不乱动”。

对一个移动台：明确允许的移动方向、行程、速度和停止位置；随后说明导向怎样约束其他运动、驱动怎样施力、行程末端如何处理、停止后如何保持位置。

检查是否过约束、欠约束、对中敏感或受热后卡死。不能把 CAD 里固定住的零件当作现实中有合理定位和支承。

### 5.5 第五步，建立整机和工位基准

1. 定义整机坐标系、方向和原点的实际物理含义。
2. 定义各工位的安装基准面、定位基准和工艺基准。
3. 给关键接口写位置、姿态、单位、允许误差和参考版本。
4. 说明加工基准、装配基准和检测基准怎样转换。
5. 对基准不一致处分析误差传递。

一根轴看起来插进孔里，不代表同轴度、配合、公差或装配路径合理。

### 5.6 第六步，划出五类空间

分别检查：实体占用空间、运动扫掠空间、工件进出空间、工具与人员操作空间、维护拆卸空间。

还应按适用情况增加管线活动空间、散热空间、落料空间及危险区域隔离空间。一个位置在静止模型里没有碰撞，不代表运动、接线或维修时没有冲突。

### 5.7 第七步，安排动作顺序和资源占用

1. 列出每步动作的开始条件、执行时间和结束信号。
2. 标明同一夹具、机械臂、工件和安全区域的共享关系。
3. 明确哪些动作可以并行，哪些必须互相等待。
4. 计算关键路径，考虑等待、稳定、检测、补料和换型。
5. 分析卡在中间时工件怎样取出、动作怎样恢复。

### 5.8 第八步，给子系统签订接口约定

每个机械接口至少写：连接双方、安装基准、位置和方向、连接形式、预期载荷、相对运动、精度要求、空间边界、装拆方向和负责人。

能源与信息接口补充：介质或电源条件、连接位置、信号含义、失效表现、互锁与恢复责任。接口变更必须通知所有使用方。

### 5.9 将理想连接、整机基准和环境支承变成可核对的对象

1. **设计为关键接头列出实际可能状态。** 接触、分离、滑移、间隙、预紧变化和局部柔度是否可能改变传力路径？按有依据的范围建模，不默认所有接触都完全绑定。
2. **知识检查模型适用性。** 材料、摩擦、阻尼、接头和地脚约束依据来自哪里，哪些只是估计？给出可观测量与补证办法，不给未知边界条件装饰性的精确数字。
3. **设计维护全局基准，反驳独立复核功能基准链。** 设计统一给出整机坐标、各模块坐标变换、定位面与方向、尺寸链起终点、跨零件和采购接口的误差来源。反驳从每一项功能精度或配合要求反向重建关联链，检查是否漏了定位关系、重复约束、最终表面状态和可形成基准的加工路径，不能只抽查几条最显眼的链。相同结构可按已复核的参数化族处理，但须列全实例、适用边界和例外；超出边界的实例单独复核。双方结果不一致时形成具体异议，不能用设计维护权代替审查。此处核查设计定义与计算依据，不假装取得尚不存在的真实几何结果。
4. **设计检查安装系统。** 框架、机脚、锚固、地面或楼板共同构成支承，记录实际可获得的现场资料和安装条件；检查加减速激励、惯性、停止精度和支承动态的耦合。
5. **反驳做功能穿透检查。** 一个外罩支架是否还决定传感器位置？采购组件是否承受样本未覆盖的侧向载荷？按实际承担功能重新定级，而不只看名称。
6. **设计核对全局兼容。** 局部最优的夹具、驱动或检测方案是否挤占共同空间、节拍、能源和误差预算？冲突由主对话协调，不由下游现场自行凑合。

**本轮产物：** 多状态载荷路径、基准链责任记录、支承条件、全局预算检查与风险分级复核。

**可以继续的条件：** 主要动作有实现路径，载荷有闭合路径，支承有物理对象，必要自由度和约束明确，接口与空间能支撑后续逐件设计。

## 流程六：逐件设计，补齐连接、螺钉、支撑和全部必要细节

**本阶段分工：** 设计主做零件、连接与装配；知识给选型和计算依据；反驳查物理、制造与互换；主对话追踪跨对象影响。

这是保证“内部完整”的核心流程。AI 必须按同一顺序逐个处理零件与接口，不能只给整机写一段宏观说明。

### 6.1 第一步，从功能和载荷链生成零件，不先凑零件清单

拿到一个功能，如“使压头沿指定方向稳定移动”，依次问：

1. 需要什么动作或约束？
2. 什么物理对象提供这个动作或约束？
3. 这个对象靠什么固定和传力？
4. 固定它的对象又靠什么支撑？
5. 哪些位置需要导向、定位、紧固、密封、润滑或检测？
6. 哪些辅助件可以由标准组件完整提供，哪些必须自行设计？

由此得到执行机构、安装件、导向、压头、连接件、限位或检测等需求。具体清单随方案变化，不能把示例套到所有机器。

### 6.2 第二步，判断这个零件是不是真的需要

给每个零件做一次“移除检查”：

> 如果把它拿掉，哪项功能、强度、精度、防护、装配或维护要求会失效？

能够回答，就把失效要求连到该零件。无法回答时，检查是否多余、重复或只是装饰。多功能零件允许存在，但必须评估它是否让制造、维修或故障后果变差。

必要件不等于必须独立制造。例如标准执行器内部的轴承和密封可以由供应商完整组件覆盖，不要求 AI 虚构其内部尺寸；要记录组件边界、额定条件、安装要求和相关证据。

### 6.3 第三步，给每个零件建立“身份卡”

| 必须交代的内容 | AI 应回答的问题 |
|---|---|
| 功能 | 它具体完成什么，关联哪些要求？ |
| 类型 | 自制件、标准件、采购组件、耗材还是工装？ |
| 接口 | 接到谁、接在哪、用什么基准？ |
| 受力与工况 | 承受哪些力、力矩、温度和循环变化？ |
| 材料与状态 | 为什么选这种材料，是否需要热处理或表面处理？ |
| 形状尺寸 | 哪些由功能决定，哪些由安装、强度和加工决定？ |
| 精度 | 哪些尺寸要控公差，为什么？ |
| 制造 | 从什么毛坯出发，怎样加工和检测？ |
| 装拆 | 以什么顺序装，什么工具能到达？ |
| 维护 | 是否磨损、如何润滑、怎样检查和更换？ |
| 证据 | 哪份计算、样本、试验或审查支撑它？ |

概念阶段允许部分字段为明确的待定项；制造交付阶段不能缺少影响该零件制造、装配与使用的关键字段。

### 6.4 第四步，逐条处理“零件 A 怎样连到零件 B”

对每条连接，固定按以下顺序走：

1. **先说目的：** 固定、定位、传递扭矩、铰接、导向、密封还是可调？
2. **再说载荷：** 拉力、剪力、弯矩、扭矩、冲击、振动和温度怎样作用？
3. **确定定位：** 基准面、止口、销、轴肩、键或其他形式怎样限制所需自由度？
4. **确定紧固或保持：** 螺纹、焊接、过盈、夹紧、卡环等怎样实现，为什么合适？
5. **确定接触与传力：** 靠摩擦、承压、形状约束还是组合？与计算模型是否一致？
6. **确定可制造性：** 孔、槽、配合面和焊缝能否加工、检测？
7. **确定可装性：** 实际装配顺序能否完成？最后一个零件是否装不进去？
8. **确定可维护性：** 必须拆哪些件，是否能安全释放储能？
9. **最后检查：** 连接两边的图纸、模型和清单是否一致？

不得把“两块板在模型里接触”视为已经建立连接。

### 6.5 第五步，螺钉具体放哪里，逐步这样确定

拿“把执行器安装板固定到框架”作为例子。此时先不指定 M6、M8 或孔数。

**第一小步：画出连接区域。** 标出安装板与框架实际接触的面，以及定位基准、载荷作用线和允许开孔的区域。

**第二小步：判断接头承担什么。** 它要承受分离拉力、平面内剪力、偏心力矩还是循环振动？这些工况来自哪里？哪些同时出现？

**第三小步：决定定位与紧固是否需要分别承担。** 如果每次拆装都要恢复精度，应分析定位面、止口或销等方式；不能默认普通间隙螺栓孔能提供所需重复定位精度。若依靠摩擦传剪，应明确预紧和接触条件。

**第四小步：提出螺钉组布置。** 根据受力、板件刚度、连接面积、已有孔位和可用空间提出孔位与数量。不能仅凭“对称好看”或“四颗比较稳”定案。

**第五小步：检查每个孔周围。** 核对边缘、薄壁、筋板、焊缝、其他孔、加工退刀和螺纹底部空间，分析局部承压、撕裂、疲劳等适用失效模式。

**第六小步：选择连接形式与真实规格。** 判断采用通孔螺栓与螺母、内螺纹孔、螺柱、嵌件或其他形式；结合被连接材料、载荷、环境和维护选择适用标准与等级。

**第七小步：计算长度与有效连接。** 累计实际夹紧厚度，考虑垫圈、螺母、螺纹啮合、孔底、导入段和装配余量。确认不会顶到底而未夹紧，也不会干涉另一侧机构。不能把统一的“几倍直径”当作所有材料和工况的最终依据。

**第八小步：检查预紧与保持。** 根据可靠依据确定预紧策略、摩擦条件、工具方法和必要的防松措施；分析重复拆装、表面处理和振动的影响。不能对所有连接随意填同一个拧紧扭矩。

**第九小步：把工具放进去。** 检查扳手、套筒或扭矩工具的进入路径、转动空间、反力空间和取出路径；检查螺母是否能够被持住。仅能在裸板上装入、整机装好后无法操作的连接要重排。

**第十小步：给出孔位与零件实例。** 用所属基准系表示位置、方向、孔型、螺纹和公差；将同一规格的每颗螺钉作为有位置的装配实例管理，BOM 汇总数量。

**第十一小步：检查松脱后果与维护。** 是否可能落入工件、食品接触区、电气区域或运动机构？是否需要防遗失设计、检修标识或规定复查？按具体风险决定。

**第十二小步：形成连接记录。** 保存计算依据、规格、孔位、配套件、装配方法、检查方式及适用版本。缺少关键条件就保持待设计状态。

这一流程同样适用于小型传感器支架。检查深度根据实际功能、载荷和失效后果调整，并由反驳复核分级；兼做定位或保护的罩壳连接不能因名称被判成低风险。不要求每颗螺钉做有限元，但需要选用与风险相称、能够回答真实问题的检查方法。

### 6.6 第六步，检查支撑、柱、板和框架

依次确认：

1. 支撑点是否位于合理的力传递路径？
2. 截面和材料是否满足适用强度、刚度、稳定性和疲劳要求？
3. 安装面的变形是否破坏导向或工艺精度？
4. 加强筋是解决真实问题，还是制造新的焊接、加工和维护困难？
5. 焊接顺序、变形、消除应力与后加工基准怎样处理？
6. 调平、锚固、地面不平和运输载荷怎样处理？
7. 若一个支撑失效，会出现怎样的后果，需不需要检测或其他措施？

输出《结构承载分工图》：谁承受主载荷、谁维持精度、谁只是防护。让审阅者可以沿图逐段查证。

### 6.7 第七步，检查轴、轴承、导轨和传动细节

对旋转轴逐项问：径向与轴向载荷从哪里来？轴承怎样支承？轴向怎样定位？热伸长如何处理？是否存在不合理的过约束？肩部、圆角、退刀、锁紧和装拆路径是否兼容？

对直线导向问：受力与力矩怎样分配？安装面精度是否能够制造？导轨间距与滑块间距是否合理？污染、润滑、限位和防坠怎样处理？

对传动问：扭矩怎样进入和输出？键、花键、夹紧或联轴器怎样选？偏心、回差、弹性和安装误差是否影响目标？传动防护和维护是否可实现？

不能只把轴穿过一个实体孔，就声称完成“轴承支承”；也不能只画一个封闭块，声称其中有未定义的传动机构。

**驱动选型再展开一遍：** 先从工况得到输出端所需运动与载荷，再考虑传动比、效率、惯量、摩擦和运动曲线，把要求换算到驱动端；检查峰值与持续能力、工作循环、温升和控制特性。随后核对安装、传感、制动或保持需求，最后选择真实配置。

垂直机构尤其要分析失能后的运动、保持方式及维修状态；不能假定电机断电就一定停住。驱动额定能力足够，也不能替代传动、支承和连接的校核。

### 6.8 第八步，检查密封、润滑、排屑、散热和管线

每项按“来源 → 路径 → 终点 → 失效后果”检查。

- 润滑：需要什么介质，从哪里加，怎样到达摩擦副，如何观察、补充和避免污染？
- 密封：密封什么介质、压差和运动？配合面和槽如何制造？磨损后如何更换？
- 排屑排废：废物怎样产生、流向哪里、会不会堵住、何时清理？
- 散热：热源在哪里，热怎样离开，温升会改变哪些精度或材料性能？
- 电缆气管：从哪到哪，怎样固定，运动处如何弯曲，是否磨碰或被夹，接头能否装拆？

采购组件有内部细节时，记录供应商覆盖范围；自制结构的关键路径不能用“内部自动处理”掩盖。

**气动、液压或真空系统再展开一遍：** 从源头能力出发，沿调节、过滤、阀、管路、接头到执行端核对流量、压降、介质兼容和实际响应；再检查排气、回流、泄漏、污染、堵塞、软管损伤和残余储能。阀的断能位置、执行器失能状态及恢复条件要与机械和控制设计一致，不能只画一根连线代表完整回路。

### 6.9 第九步，做公差、间隙和最不利组合检查

1. 选一个真实功能，例如压头与孔的对中。
2. 沿装配基准找出影响它的尺寸、形位、安装和变形来源。
3. 区分制造误差、装配误差、受载变形、温度变化和磨损。
4. 先按已知的最终状态公差范围分析最不利组合；采用统计方法时，必须有与对象、工艺和来源相匹配的分布、相关性及过程稳定性依据，不能默认正态、独立或把缺数据解释成统计可放宽。输入范围本身不可信时，最不利计算也只能作为假设分析，须保留缺口。
5. 检查要求能否在现实制造能力下达到。
6. 不满足时修改结构、基准、调节办法或工艺；不能只把图纸公差写得极小。
7. 确定如何测量和验收这些要求。

### 6.10 第十步，做一次完整装配与拆卸演练

从散件开始，按真实顺序模拟：先装哪个、如何定位、如何支撑、从哪个方向放入、用什么工具紧固、什么时候调整、怎样检测。

随后反过来演练更换高频磨损件。检查是否存在“轴承装入后无法安装锁紧件”“罩壳装完后再也拧不到螺钉”“换一个传感器必须拆掉整套基准”的问题。

若必须依靠专用工装才能完成，工装也需要明确设计或采购任务，不能隐去。

### 6.11 第十一步，做内部完整性检查

| 检查 | 判定方法 | 不通过时回哪里 |
|---|---|---|
| 原始任务没有被静默丢弃 | 原始动作逐一对应现有功能、机构及成功判据；阶段七独立反查 | 3.8、流程四 |
| 功能有承载对象 | 每项必要功能连接到零件或明确的采购组件 | 6.1 或流程四 |
| 必要零件有理由 | 每个零件关联需求、接口或维护作用 | 6.2 |
| 力有传递路径 | 每个关键载荷可追到反力与支承 | 流程五 |
| 零件有连接 | 每个装配实例有实际连接或有意允许的相对运动 | 6.4 |
| 紧固件数量一致 | 模型实例、连接记录和 BOM 相符 | 6.5 |
| 孔位与配套件一致 | 连接双方孔、螺纹、销与基准一致 | 6.5、6.9 |
| 标准件是真实对象 | 型号、配置、额定条件和安装资料可追溯 | 6.3 |
| 运动不靠“固定”假设作弊 | 约束对应真实导向、支承或连接 | 5.4、6.7 |
| 能源介质有完整路径 | 起点、连接、末端和异常状态已定义 | 6.8、流程七 |
| 能装、能拆、能调 | 装配步骤与工具路径可实现 | 6.10 |
| 关键结论有依据 | 当前版本的资料、计算、已有实测和独立复核支持当前设计结论 | 7.10 |

**先做全量底线核对，再决定哪些地方加深。** 每个零件实例及每个连接都必须核对必要性、实际功能、位置与方向、相邻对象、受力或非承载理由、定位与约束、装拆路径和适用规格；已有可靠标准组件可引用其边界明确的资料，但安装位置和实际接口仍要逐个落位。不能因为被叫作“小支架”“普通罩壳”便完全免查。

**再跨对象检查共同作用。** 沿同一条载荷、基准、线缆、流体或维护路径检查一组小件，确认它们叠加后不会改变整体支承、磨损路径、排液或可达性。相同结构族可以复用经复核的设计依据，主对话保留实例覆盖表；差异和越界项单独检查。这适用于几件到大量模块，不以示例零件数量为上限。

图关系能发现缺项，但不能证明物理正确。设计仍须给出当前深度的受力、材料、连接与制造依据；反驳检查原始输入和适用假设，不能把“计算文件存在”直接写成“计算成立”。依赖尚不存在的对象才能核查的内容保持明确待核查，不伪造结果。

### 6.12 对关键内部结构增加物理和制造层的证据检查

1. **紧固接头。** 设计把拧紧扭矩视为装配输入，进一步分析预紧范围、摩擦、接触分离、撬动、滑移、螺纹承载和循环载荷。知识提供适用依据，反驳检查最敏感假设；关键接头按项目需要安排装配校准、接触或预紧评估、复测和耐久证据，不能只核对扭矩记录。
2. **刚度和精度。** 从真实工艺允许误差分配变形预算，分别检查零件、连接和支承的柔度；应力通过不能关闭精度异议。必要时将受载位移与实际可测位置关联。
3. **焊接与长期稳定。** 明确焊接、热处理、后加工、释放应力及检验时序；评估焊接接头疲劳和残余变形对安装精度的影响，实际能力与耐久证据不足时标待验证，不能只在模型中设为刚性连接。
4. **装配顺序和装配资源。** 用真实先后约束、可达路径、临时支撑、设备所需力或能量、温控及工具建立装配过程；分析关键拧紧顺序造成的变形。目标是求得并验证可执行顺序，不宣称穷举所有排列即可保证装配。
5. **制造与测量能力。** 工艺方案需对应实际供应商、机床或方法、批次和检验能力；最好一次加工结果不能代表持续能力。统一温度、夹持、基准拟合和评价方法，考虑测量不确定度对接受边界的影响，不捏造通用过程能力阈值。
6. **最终状态公差链。** 将镀层、涂层、热处理、毛刺处理和后加工状态纳入配合与尺寸链；图纸明确哪些表面加工、哪些保留或保护。先加工合格不代表最终交付态合格。
7. **互换设计。** 按 3.8 的用户要求，明确允许来源、配置修订、最终状态尺寸与公差、定位面、孔组、轴肩止口、安装方向和拆装空间；检查规定来源内的边界配合组合。型号相同不自动兼容，资料未给的关键接口列为缺口。若需要选择装配或调整，先判断是否符合需求，不得仅靠写明限制就自行降低直接互换要求。未核实的供应商与配置不能算进已覆盖集合，临时扩孔或敲装不能成为默认设计方法。
8. **清洁和调整。** 定义装配清洁、介质冲洗、封存及异物检查要求；在装完罩壳与管线的状态下验证调整工具和测量可达性，而不是只在裸机上检查。
9. **风险分级二次检查。** 设计提出低风险或标准组件边界后，反驳核对实际功能、载荷及失效影响。没有充分依据不得降低检查深度；专业能力不足记录为未知，不能改成不适用。

**本轮产物：** 关键接头设计依据、最终态公差与测量约定、装配资源及顺序、来源明确的接口与互换边界、风险分级复核和仍缺少的事实。设计估算、真实资料和已有实测分别标记。

**可以继续的条件：** 当前设计深度需要的内部结构已经具体化；拟提交的详细规格不能遗留未定义的承载连接、缺少规格的关键紧固件、无支承的运动件或只有口号的装配路径。范围不清的接口保留待设计，不算内部完整。

## 流程七：把机械、电控、安全、制造、装配和维修整合起来

**本阶段分工：** 主对话落实跨专业责任；知识补充依据；设计整合机械、电控与维护；反驳查失能、时序、退化和人员条件。

### 7.1 第一步，逐个动作连接执行器、传感器和控制条件

拿一项动作，例如“压头下行”：

1. 谁提供能量与驱动？
2. 哪些条件满足才允许开始？
3. 怎样知道工件、夹具和防护状态满足条件？
4. 通过什么信号知道动作已经结束？
5. 信号缺失、相互矛盾或超时时怎样处理？
6. 失去电源、气源或控制信号后机构会怎样运动？
7. 恢复供能后，怎样防止未经允许的意外动作？

每个传感器必须有检测对象、检测原理、安装位置、安装公差、线缆路径和故障含义。不能仅在清单中写“若干传感器”。

### 7.2 第二步，检查整机状态转换

至少判断是否需要：停机、准备、回原点、手动调整、自动运行、暂停、缺料、满料、故障、维护和恢复状态。

对每次转换写：触发条件、允许动作、禁止动作、退出条件和工件状态处理。不同工况的安全功能需专门设计；普通控制程序中的一条判断不能自动等同于经过验证的安全功能。

### 7.3 第三步，把风险检查贯穿机器生命周期

按运输、安装、调试、正常使用、补料、清洁、卡料处理、维护和拆除逐项检查风险。

机械设计应考虑危险识别、风险评估和降低风险的措施，并保存相关记录。ISO 12100 的公开说明覆盖这类方法；具体项目仍需确认适用地区、行业与设备类别的要求，不能仅凭引用标准名称就声明合规。[依据：ISO 12100 官方说明](https://www.iso.org/standard/51528.html)

对每项风险给出：危险来源、谁会暴露、发生条件、设计措施、需要的检测或保护、剩余风险和验证方式。优先研究能从结构和工艺上减少危险的方案，再结合必要的保护及使用要求。

安全功能所需性能、停止距离、储能释放和特殊行业要求，应依据具体风险与适用标准确定；本通用流程不写一套适用于所有机器的固定值。

### 7.4 第四步，按真实制造条件推演零件怎样做出来

对每个自制件依次检查：毛坯怎么买、夹哪一面、刀具能不能到、先加工什么、热处理或焊接后会怎样、最终基准如何形成、关键尺寸如何测量。

发现加工不到的内腔、无法检测的公差或无法稳定加工的薄壁时，回流程六改结构。必要的专用工装、量具和外协能力必须计入项目。

### 7.5 第五步，按装配者视角推演零件怎样装起来

检查吊装与临时支撑、定位顺序、紧固顺序、调整方法、清洁要求、注油或排气、检查点和返修路径。对需要校准的量，说明调哪里、测什么、如何锁定并记录。

物理系统有实际误差。需要校准和调整的地方应保留可操作办法，不能为了结构简洁而假定加工与传感永远准确。

### 7.6 第六步，按维修者视角推演一次典型换件

选出最可能更换的件，例如密封、轴承、夹爪、传感器或刀具。逐项确认：

1. 怎样发现它快坏了？
2. 怎样进入适当的检修状态并处理储能？
3. 要拆哪些件，用什么工具？
4. 拆除后是否破坏关键基准？
5. 新件怎样装、调、验？
6. 备件来源、交期和可替代范围是什么？

### 7.7 第七步，核对成本、交期和采购真实性

估算设计方案的总成本时，不遗漏主要采购件、加工件、装配调试、软件电控、工装量具和必要检查的成本。这里只比较方案代价，不组织这些工作的执行。供应商资料应记录型号、配置、版本和获取日期；无法查证的型号保持候选，不能当作已确认选型。

替代型号需要重新检查尺寸、接口、额定能力和控制条件，不可仅因名称相似而自动替代。

### 7.8 按实际运行过程联合检查机械、电控、人和环境

**先检查信号是否代表真实状态：** 设计说明传感器看到什么、检测原理、反光与污染影响、安装公差及标定方法；把机械动作、传感触发、滤波、通讯和控制响应画到同一时间线上。知识提供边界条件，反驳检查“信号到位而工件仍未稳定”的反例，主对话指定接口责任，不能让机械和控制相互假定对方已经处理。

**再检查失能和故障组合：** 从每个执行器、阀、重力载荷、残余压力和自锁条件建立状态表，按危险后果和共同原因选择组合；列出安全状态、异常传播、恢复前提和工件身份。单个故障检查不能替代组合；也不承诺穷尽所有组合。对单点失效、隐蔽失效，比较可检测性、隔离和适当的冗余措施，并检查共同原因，不能机械地多装一个传感器就称安全。

**安全功能单独落责任：** 主对话记录专业设计与验证任务，知识核对适用依据，设计给出实际架构，反驳核查证据。所需性能和验证来自该项目风险与适用要求；普通输入上的急停或一般报警不能冒充已验证的安全功能。本框架不预设通用性能等级，也不把专业签字本身当技术证据。

**接着设计时间中的机器：**

| 变化对象 | 设计与知识需要做什么 | 反驳怎样检查 |
|---|---|---|
| 载荷谱、磨损与精度保持 | 定义任务周期和寿命指标，采集或给出有依据的探索范围，安排长期或合适加速试验 | 是否拿假谱当实际寿命；加速条件是否改变失效机理 |
| 换型与重复紧固 | 分析次数、定位磨损、预紧衰减及恢复精度 | 是否只验证第一次装配或第一次换型 |
| 热与长尺寸链 | 分析从冷机到稳定运行的温度、热变形及精度传递 | 是否只检查瞬时温升，遗漏结构和公差耦合 |
| 腐蚀与清洗介质 | 核对实际材料状态、清洗液与接触条件，并按需取证 | 是否凭材料名称默认适用 |
| 润滑与运动副污染 | 定义入口、密封排污、补给、检查方法和维护偏离时的后果 | 润滑点是否可达、可识别，漏做后是否无声失效 |
| 拖链与活动线缆 | 记录弯曲次数、半径、行程、速度、环境与固定方式 | 年限是否掩盖实际循环；接头和安装是否改变寿命 |
| 电柜热、尘和凝露 | 检查工作与停机环境变化、过滤和维护方案 | 冷启动与长停机后是否出现未覆盖条件 |
| 气源水油和污染 | 明确介质质量、处理与检查要求，核对现场能力 | 是否假定现场气源等于理想供气 |
| 长期停机与重新启用 | 定义保存、检查、清洁润滑、校准和受控复机任务 | 恢复供能是否被误当作恢复可生产状态 |
| 动物或意外异物进入 | 按现场证据评估通道、侵入和损伤机理，提出合适防护与检查 | 是否只保护正常工作区，遗漏停机与维护开口 |

**然后检查真实使用者能否理解并完成操作：** 主对话收集不同技能和班次人员的实际做法；设计推演搬举、弯腰、伸手、补料、报警识别和误操作后果。用任务脚本向真人核对理解，而非只写“加强培训”。询问生产节奏是否促使省略质量步骤，使正常操作可行、负担合理，并明确异常处理所需的设计条件。

**最后检查运输与安装资源：** 设计分解重量、重心、支撑、临时约束、模块接口、吊装与运输路径、到场设备及安装条件。需要专业确认的承载和吊装事项交实际有能力人员核查，不能用“已考虑运输”代替可执行计划。

**本轮产物：** 机械与信号时序、失能状态和异常传播表、安全设计要求、退化与维护约束、人员操作脚本、运输安装所需的结构与接口条件。

### 7.9 把“同一台机器在不同状态下”一起考虑

**第一步，列对象状态。** 按项目需要区分裸机与完整外罩、管线是否装齐、冷态与热态、干净与污染、空载与负载、初装与换件后、生产与维修状态。不是每台机器都套同一清单；设计必须说明本设备有哪些会改变配合、受力、控制或可达性的状态。

**第二步，选择有机理关联的组合。** 例如罩壳装好后，热膨胀、线缆摆动和维护工具空间可能共同作用；排屑、排液与重力方向也可能耦合。由反驳查漏，记录为什么选某组合、哪种组合被排除及理由，不能把每个因素分别考虑过当作联合覆盖。

**第三步，对每个选定状态推演同一任务。** 依次查动作路径、载荷与支承、接触与间隙、线缆管路、检测条件、装拆与工具空间。写明受影响对象、允许边界、当前依据和未决设计项。不能用一个静态外形图证明所有状态都可用。

**第四步，让环境变化有设计上的应对。** 对已识别的温湿度、污染、来料变化、磨损、供能波动和人员操作差异，明确适用范围、需要被观察的量、超出范围的影响，以及所需的防护、清洁、可调节结构、检测或恢复条件。范围没有可靠数据就标待确认，不编造阈值；冻结设计版本不等于工厂永远不变。

**第五步，保存未覆盖范围。** 用机理、敏感性与现有现场资料选择组合，不能声称穷举开放世界。反驳还应从原始任务寻找清单外的挑战，避免四个角色只是重复同一张表。

产物是“机器状态 × 任务 × 影响对象”的设计检查表及环境适用边界，供本轮整合设计使用。

### 7.10 独立反驳整份设计，先查任务，再查内部

1. **主对话冻结本轮提交版本。** 同时给反驳原始任务、事实来源、设计规格、完整对象清单、参数依据、已有计算和未决项，不能只给作者写的成功摘要。
2. **反驳从原始动作反查到最终实现。** 对 3.8 的每一项原始动作，逐项追到当前功能、实现机构、相关零件与连接、输入条件和成功判据；再沿完整任务检查动作之间的交接和异常恢复。设计自己画完对应箭头不算独立复核。若整机能动却少了主要生产动作，退回需求或路线阶段。
3. **检查内部对象的全量底线。** 依据 6.11 核对全部设计实例和连接，找漏件、悬空件、虚构支承、未定义孔组、错误定位和缺失配套件。复用结构族的结论须可对应所有实例，不能用一件合格代表所有不同配置。
4. **复核全局基准与耦合。** 按 5.9 从功能出发独立核对基准链；再检查共享空间、整机误差、载荷反力、能源和节拍预算，以及 7.9 的联合状态。局部预算合格不等于整机总量合格。
5. **对关键计算检查物理前提，而不只核对算式。** 知识提供来源与适用条件；反驳根据功能、后果和敏感性，检查材料状态、载荷方向、接触、预紧、摩擦与支承。可用独立数量级估算、另一种适用推导或可追溯的外部资料复核；不能换一种表达重复原计算就声称独立。涉及其能力之外的问题明确保留缺证。
6. **识别同源证据。** 多份报告若使用同一批样本、同一参数或同一假设，应标为同一来源组。已有试验与计算若由同一组数据选型或校准，吻合不能自动算独立支持；优先寻找未用于定参数的已有样本、不同来源记录或能揭示其他失效机理的资料。不存在这种资料时如实保留局限，不在本文件虚构执行结果。
7. **核对制造、装配和维修推演。** 关键表面怎样形成、怎样测；零件怎样放入、支撑、定位、拧紧；关键件怎样取出并恢复基准。互换能力必须对应用户要求和明确的来源边界，不能靠型号名称或“允许调整”掩盖不兼容。
8. **给出有对象的结论。** 对每项异议写明违反什么要求、在哪个对象和状态出现、证据或待补事实是什么、回到哪一步修改以及怎样关闭。没有发现问题仅表示当前审查未发现阻塞，不表示内部永远正确。

主对话用一页摘要呈现最重要的设计决定、未决项和可继续工作，细节按机构、零件、连接逐级索引。简化呈现不能省略对象覆盖，也不要求每个标准件重复写一篇完整论证。

### 7.11 修改要落到受影响对象，不能只修改解释

**先判断问题属于什么。** 原始任务理解错，回阶段一至三；完整任务路线不成立，回阶段四；载荷、自由度、基准或接口冲突，回阶段五；零件、连接、孔位、公差或装拆错误，回阶段六；联合状态与控制条件遗漏，回阶段七相应小步。

**再修改真实设计定义。** 设计写明改动原因和受影响对象。例如工艺力增大，要检查执行器、压头、夹具、承载框架、安装板、紧固件、支承、变形和动作预算；不能只把需求表里的数字换掉。不能确定影响边界时扩大复核范围，并记录原因。

**然后使旧结论过期。** 主对话保存原版本，把相关参数、接口、计算、覆盖结论和异议关闭状态关联到新版本；明确哪些需要重做，哪些有依据可以沿用。新增对象和删除对象都要重新检查原始任务是否仍完整。

**最后由反驳复审。** 设计提交修改和依据，知识补充适用性，反驳按原关闭判据判断是否解决并检查新问题。主对话不能用“已修改”直接替代“复审接受”。连续争论没有新证据时沿用协作 4 的取证规则，不为了结束对话强行通过。

### 7.12 输出一份能继续工作的完整设计规格

**第一步，先声明范围。** 写清本轮任务、需求版本、已完成设计的模块、仍属探索的对象和剩余缺口。只有局部完成就交局部，不把整机标题当作整机已完成的证据。

**第二步，按从整机到连接的顺序整理。**

| 层级 | 必须让接收者看明白什么 |
|---|---|
| 原始任务与要求 | 原话来源、工件与工艺边界、原始动作、成功判据、明确禁止或必须满足的条件 |
| 路线与整机 | 为什么选择该原理、完整任务周期、辅助功能、候选淘汰理由、整机资源与误差预算 |
| 骨架与接口 | 总体坐标与方向、机构轴线、跨模块变换、载荷与反力路径、基准链、共享空间和接口责任 |
| 每个机构 | 输入输出、运动范围与自由度、驱动导向支承、主要状态、时序、异常与恢复条件 |
| 每种零件 | 必要性、材料或可追溯型号配置、几何定义与尺寸依据、最终状态公差、工艺与检查要求 |
| 每个装配实例 | 所属模块、位置姿态、定位对象、连接对象、允许相对运动、操作和维修空间 |
| 每个连接与孔组 | 传力和定位分工、连接形式、位置方向、孔型与配合、紧固件及配套件、装拆顺序和依据 |
| 控制与能源接口 | 动作与状态条件、传感对象与安装条件、供能与管线、失能行为和安全设计要求 |
| 现实变化 | 联合状态、环境适用范围、磨损与调整、备件互换边界、制造装配维护所需条件 |
| 设计依据与审查 | 参数来源、估算与事实区分、计算假设、独立复核、异议处理、未决项及其影响 |

**第三步，检查能否按规格定位每个细节。** 接收者应能回答“这根柱为什么承载、受什么力、两端怎样连”“这颗螺钉在哪里、连接谁、孔怎么定义、用什么工具装”“这个采购件换成规定来源的另一件，会改变哪些接口”。回答停留在“按需选取”“若干”“后续再想”的必要细节，不算详细设计完成。

**第四步，最后再从用户任务反查一遍。** 反驳核对原始动作与当前设计规格对应关系，没有遗漏、偷换目标或未经确认的要求降低。整合和删改文件后也要复查，防止内容在汇总时丢失。

**第五步，提交范围明确的结论。** 主对话只声明“该版本、该范围的前七阶段设计规格可提交”，列出适用条件和未决项。不声称本轮已完成实际工程执行，不把没有取得的现实证据写为通过。

**前七阶段结束条件：** 原始任务有完整实现路径；内部必要对象、承载、定位、连接、孔位和装拆已达到约定设计深度；全局接口及联合状态已审查；影响本轮设计规格成立的阻塞已经关闭；保留的未知有明确对象和影响范围。达不到这些条件时，交出已完成部分及具体缺口，保持相应设计状态。

## 贯穿七个阶段：AI 每次怎样决定下一步

### A. 固定执行这条小循环

```text
读当前目标、版本和未决项
    ↓
找到一个现在必须完成的决定
    ↓
已有证据够不够？
    ├─ 够：形成候选结论 → 做相应检查 → 记录结论与依据
    └─ 不够：缺的是哪一类信息？
               ├─ 工厂事实或业务偏好 → 问用户
               ├─ 元件、材料或标准资料 → 查可信来源
               ├─ 能推导的工程量 → 计算或调用工具
               ├─ 未知真实行为 → 请求已有实测或说明所需事实，保留设计缺口
               └─ 信息冲突 → 展示冲突并澄清
    ↓
更新需求、参数、零件、连接和证据
    ↓
让受影响的旧结论过期
    ↓
检查当前允许继续做什么
    ↓
选择下一项工作
```

等待时可以继续处理独立工作。依赖未解决问题的工作保持等待，不通过假设一个答案解除等待。

### B. 每次向用户提问采用这个格式

> **现在要决定：** 夹具应该支撑工件哪些位置。  
> **需要你说明：** 壳体底面和外侧面，哪些允许接触？密封槽和外观面有没有禁触要求？  
> **原因：** 支撑位置会影响压装时的变形和表面损伤。  
> **你不知道也可以：** 我会列出需要产品人员确认或样件试验的项目，先保留未定状态。

通常一轮一个关键决定；紧密相关的事实可以一起问。问题要适合工厂使用者回答，工程推导由 AI 和工具承担。

### C. 收到答案后不能只说“好的”

固定做六件事：

1. 保存原话和来源。
2. 判断属于事实、偏好、授权、估计还是“不知道”。
3. 提取数值、单位、范围、条件和适用规格。
4. 检查与已有记录是否冲突。
5. 告诉用户这条答案改变了什么决定；没有必要时不重复整份需求。
6. 更新依赖对象、工作计划和验证任务。

例如用户说“底面可以支撑，但密封槽不能碰”，应更新禁触区、支撑方案、夹具接触面和装配空间；不能只把这句话放在聊天历史里。

### D. 何时不再问用户

停止提问的条件是当前决定所需信息足够，并且没有未处理的关键冲突。不是问满固定题数。

AI 自己能够计算、查证或在授权范围内决定的事项，应主动完成。用户已提供可靠资料时不要重复问；用户已授权低风险的内部设计选择时，不要每颗螺钉都再次征求同意。

但 AI 必须完成螺钉设计本身的检查，不能把“无需用户决定”误解为“不用考虑”。

## 一段完整演示：从一句需求到内部结构修改

**教学任务：** 用户想做一台异形壳体自动装配和检测设备，产品包含密封圈、衬套与紧固件。以下全部回答与数值是虚构示范，真实项目必须重新获取。

本演示中，所有用户问题由需求与规划主对话提出；知识提交依据和缺口，设计提交实现与修改，反驳提交具体异议并复审。各轮不等于七阶段编号，问题出现时返回受影响步骤；以下不执行实际制造或设备试验。

### 第 1 轮：先知道整机干什么

**主对话问：** “请按现在工人的操作顺序讲，一件壳体怎么变成合格成品？”

**示范回答：** “放壳体，装密封圈，压衬套，锁紧四颗产品螺钉，测漏，分到合格箱或不合格箱。”

**主对话组织处理：** 建立工艺草案和产品状态变化，区分产品自带的四颗螺钉与机器自身的连接螺钉。此时不能把产品螺钉数量误当设备紧固件数量。

### 第 2 轮：知道哪些东西会变

**主对话问：** “必须支持几种壳体？它们的定位面、密封槽和衬套位置相同吗？”

**示范回答：** “三种，底面相似，但衬套位置不同。”

**主对话组织处理：** 建立三个产品版本，提出共用底座加换型模块和全可调夹具两条路线。先收集尺寸和基准，不立即选其中一条。

### 第 3 轮：把产量变成节拍约束

**主对话问：** “每小时需要多少合格件？这段时间是否包含补料、换型和停机？”

**示范回答：** “稳定生产时至少 240 件合格品；换型时间另外考核，补料和一般停机要计入。”

**主对话组织处理：** 算出平均每 15 秒需要一个合格品。这只是目标产出的时间预算，不是直接规定每个动作 15 秒，也不是把理想循环设为 15 秒就必达产量。继续考虑不良、停机、并行和缓存。

### 第 4 轮：发现关键未知，先安排取证

**主对话问：** “衬套压入过程有没有力位移记录或允许损伤标准？”

**示范回答：** “没有，工人凭手感；不能压裂壳体。”

**主对话组织处理：** 写明需要压装力与产品尺寸、批次、速度、损伤条件的对应资料。执行器、夹具和框架强度暂不冻结；可继续研究上料和换型方式。

### 第 5 轮：确定能在哪接触工件

**主对话问：** “哪些表面可以定位和支撑，哪些是密封面或外观禁触面？”

**示范回答：** “底部指定台阶可支撑，密封槽禁止接触。”

**主对话组织处理：** 把允许支撑区域与禁触区域标入工件定义。所有候选夹具都受它约束；不能靠把夹具画在看不见的内部规避。

### 第 6 轮：新数据回来，推导受力结构

**示范新资料：** 真人提供一份已有样件记录，其中有对应条件的压装力范围，但尚未覆盖所有批次。

**主对话组织处理：** 核对来源后，根据该范围建立当前工况与剩余数据缺口，设计压头、工件支承和受力框架的反力路径。判定哪部分承担压装反力，哪部分只是导向和罩壳。

**此处不能做：** 把有限样本直接表述成所有工况均已验证；也不能只选择一个足够大的执行器就宣布压装模块完成。

### 第 7 轮：把结构细化到接头

**设计子代理执行，反驳复核：** 对执行器安装板与框架接口按流程 6.5 逐步确定定位、螺钉组、孔位、规格依据、夹紧长度和工具空间。记录其受力与计算输入。

**何时再问用户：** 若工厂规定只能使用某些紧固件系列、工具或维护方式，而且已有资料没有说明，再问。孔位与数量的工程推导由 AI 完成。

### 第 8 轮：发现外形看不出来的装配问题

**反驳提出异议：** 按当前空间和装配顺序，安装罩壳后，后侧连接的紧固工具没有进入路径。异议指向具体连接和罩壳版本，该部分设计保持待修改；关闭条件是给出有依据的装拆路径并复核受影响的空间与结构。

**主对话组织处理：** 比较调整连接方向、设置合理检修开口、改变模块装配顺序或重排部件。检查修改对防护、刚度和维护的影响，更新内部与外部结构。

**复审：** 设计提交修改与受影响对象，知识核对必要约束；反驳检查工具路径、防护和结构影响，主对话在关闭条件满足后提交新版本。

**此处不能做：** 把工具空间问题写成“安装时注意”然后放行。

### 第 9 轮：处理现实异常

**主对话问：** “压装中途停机的半成品，工厂允许返工、人工判定还是必须报废？”

**示范回答：** “需要工艺人员判定，不能自动当合格品流走。”

**主对话组织处理：** 增加在制品身份与异常状态处理要求，设计受控恢复条件，核对夹具是否能按维护要求释放工件。

### 第 10 轮：校核节拍时推翻初始布置

**检查结果：** 测漏的稳定与测量时间超过了单工位目标预算。

**主对话组织处理：** 比较并行检测、调整工序布局或重新讨论产量目标；判断增加的工位、夹具、管线与成本。需要用户决定成本和产量权衡时，展示具体方案再问。

**此处不能做：** 擅自缩短未经验证的测量时间，使结果看起来满足节拍。

### 第 11 轮：反驳发现“各机构都有，却没完成原始任务”

**示范发现：** 设计有上料、压装和检测机构，但遗漏检测失败后的工件去向，仍把所有产品送入合格品出口；另一处夹紧估算只按局部接触，未考虑薄壁壳体的实际支承。

**主对话组织处理：** 从原始动作表核对要求；设计补全分流与工件状态，重新检查对应空间、连接、传感和时序，并根据现有工件资料复核夹紧与支承。缺少材料或接触资料时，指出具体未知，不能自行编一份实测值。

**反驳复审：** 检查修改是否真正改变机构与接口，是否挤占另一工位空间，支承依据是否成立。文字写了“已考虑不良品”不算解决。

### 第 12 轮：交出前七阶段设计规格

按 7.12 整理任务对应、骨架、机构、零件、连接、螺钉孔位、控制接口、装拆、公差、现实边界和审查记录。反驳再次从原始任务核对，主对话提交实际达到的设计范围。

这个案例不要求其他设备都采用压装、夹具或分流。搬运、处理、检测、连续生产、多机协作等项目，要根据自己的任务、机理和约束生成相应对象。共同要求是每个答案改变具体设计，每个设计决定有来源，每个缺陷能回到具体对象。

## 怎样把“覆盖 99% 场景”变成能验收的目标

### 第一步：明确覆盖对象

目标域是：**工厂中基于已有物理原理的非标自动化设备与工装的前七阶段 AI 设计**。包括新产品、新组合和复杂多工位系统，不要求预先见过相同整机；评价对象是设计任务及规格质量。

这不等于保证世界上任何未知设备都能自主设计成功。涉及未知物理原理、资料不足或专门资质的项目，流程必须识别并转入相应研究或专业工作。识别得正确是流程能力，但不能算成已经完成该设备设计。

### 第二步：从实际使用场景建立清单

下面作为首批场景维度，实施前应加入用户实际订单与目标行业的代表案例。

| 场景维度 | 应覆盖的情况 | 应触发的具体流程 |
|---|---|---|
| 搬运与供料 | 托盘、散料、随机姿态、混料、缠绕、柔性件 | 来料边界、抓取原理、卡料与恢复 |
| 装配与连接 | 压装、螺纹连接、卡接、铆接、插入、密封 | 工艺窗口、支撑、连接与质量判定 |
| 加工与处理 | 切削、切割、去毛刺、成形、点胶等 | 工艺力、工具、排废、污染与耗材 |
| 检测与分选 | 尺寸、视觉、泄漏、力、功能和追溯 | 基准、测量能力、误判与分流 |
| 物料形态 | 刚性、柔性、易碎、薄壁、粘性、带油带水 | 接触、变形、污染和样件验证 |
| 运动形式 | 直线、旋转、分度、多轴、机器人、连续运动 | 自由度、驱动、碰撞和时序 |
| 能源形式 | 电动、气动、液压、真空、热与组合系统 | 能量路径、储能、泄漏与失能状态 |
| 结构尺度 | 小型精密、一般设备、大质量与高惯性 | 刚度、振动、稳定性、搬运安装 |
| 产品变化 | 单品、多规格、频繁换型、小批量混流 | 模块接口、防错、配置与参数管理 |
| 环境变化 | 粉尘、油雾、冲洗、温湿度、腐蚀、洁净 | 材料、防护、密封和维护 |
| 人机关系 | 人工上料、半自动、全自动、共享空间 | 操作条件、防护、安全与恢复 |
| 项目现实 | 预算不足、交期紧、资料缺失、旧线改造 | 冲突处理、取证、分阶段交付 |
| 制造现实 | 加工能力不足、焊接变形、公差偏差、供应替代 | 可制造性、检验和变更复核 |
| 生命周期 | 安装、换型、磨损、维护、运输和报废 | 装拆、寿命、备件和现场反馈 |
| 特殊要求 | 食品医药接触、压力、高温、易燃环境等 | 明确专用要求、证据和专业审查任务 |

这张表不是覆盖率分母本身。需要把维度组合成有输入、有期望行为、有验收标准的案例。仅把“考虑过高温”打勾，不能称覆盖高温机械设计。

### 第三步：每个案例都要穿过现实情形

至少选择适用的正常情况、边界情况、可预见异常和维护情况，并检查它们的相互作用。例如：

- 薄壁壳体 + 来料偏差 + 压装 + 高节拍。
- 柔性密封圈 + 带油 + 自动供料 + 卡料恢复。
- 重载升降 + 断能 + 偏心 + 维修进入。
- 精密定位 + 温升 + 螺纹连接预紧变化 + 反复拆装。
- 易清洁设备 + 藏污死角 + 紧固件脱落 + 清洁剂兼容。

组合可按风险和常见程度选择；不能声称抽几个单因素样例就穷尽所有组合。

### 第四步：只统计本文件负责的设计能力

| 指标 | 分子与分母 | 不得混淆的地方 |
|---|---|---|
| 流程处理覆盖率 | 正确推进、追问、保留阻塞或识别能力边界的案例 / 全部有效案例 | 正确拒绝一个任务不等于设计成功 |
| 设计完成覆盖率 | 达到事先约定设计深度的案例 / 事先纳入的目标设计案例 | 只有漂亮外观或只有问题清单不能算完成 |
| 内部设计完整性达标率 | 原始功能、内部对象、连接、基准、装拆与联合状态达到判据的设计 / 被审查设计 | 数据齐全不等于现实可靠性已被证明 |

目标场景、复杂度、输入完整程度和通过判据在运行前确定，不能失败后删除困难案例。分别列出成功、失败、缺事实和能力不足；给出分子、分母及未覆盖范围，不只报一个百分比。

### 第五步：检查是否只会做教学例子

使用与设计作者相分离的案例评审，纳入用户真实任务、陌生产品、多工位耦合、共享资源、供应差异和已有故障资料。保留一部分未用于修改规则的挑战案例；同一套示范参数反复通过不能当泛化能力。

新发现的场景保留失败记录，加入下一版评价集合；新旧版本的分母和标准分别保存。按机理分组复核薄弱点，不能只以设备名称不同制造大量重复案例。

### 第六步：限制结论的范围

反驳检查案例是否偏易、原始任务是否被简化、困难组合是否漏掉、缺资料是否被算作成功、原始要求是否被悄悄降低。任何比例都不能抵消必须满足的硬约束。

允许的表述应是“在某版本、某目标域、某组输入和某设计深度下，N 个案例中 M 个达到判据”。**本版未进行覆盖率实测，不能声明已经覆盖现实世界 99% 的机械设计。**

## 七阶段设计材料怎样组织，才能不丢内部细节

主对话维护一份可追溯的设计索引，不以聊天记忆代替完整记录：

1. **原始任务与事实。** 用户原话、现场来源、工件版本、已知范围、估计和未知分别保存。
2. **要求与功能。** 原始动作对应要求、功能、机构及成功判据，保留变更理由。
3. **全局骨架与参数。** 坐标、轴线、基准、载荷、空间、时序和预算有唯一当前版本。
4. **零件、实例与连接。** 同规格八颗螺钉是一个规格、八个位置实例；每个位置有连接双方、孔组与装拆条件，数量再汇总。
5. **来源与设计依据。** 记录资料适用版本、计算输入与假设、同源证据关系，估算不升级为测量。
6. **问题与复审。** 保留对象、版本、异议、责任角色、关闭判据、处理结果和仍受影响的工作。
7. **交接规格与限制。** 只引用当前有效内容，说明哪些是已完成设计、哪些仍为探索或待补事实。

复杂机器分模块组织，但跨模块连接、共用基准、共享能源及异常传播必须保留在整机索引中。任何模块更新都应检查跨模块影响，不能仅因各自文件自洽就接受整机设计。

附件中的文字、检索资料和工具结果只是输入材料，不能自行变成用户确认、权限或已通过的审查。具体存储、代码和外部工具实现不在本文展开。

## 用这些反例检查前七阶段是否真的有效

下表是设计框架的检查案例，不是已经运行或通过的测试结果。

| 输入或缺陷 | 七阶段内应出现的行为 |
|---|---|
| 用户只说“做一台快而稳的机器” | 主对话问实际输入输出、工艺、合格产出与现场边界，不直接生成外壳 |
| 四个角色把同一工艺词理解错 | 用原始任务经历、已有样品或现场资料反查，而非以四票一致作结论 |
| 局部机构能动，但反力使下一动作失效 | 阶段四整机任务推演发现耦合，调整路线或保留阻塞 |
| 最后规格静默丢掉一个原始生产动作 | 7.10、7.12 独立反向核对失败，回到对应需求或方案 |
| 有执行器和压头，却没有反力与支承路径 | 阶段五、六要求具体支承和承载连接 |
| 外罩被默认当承重结构 | 按真实功能核对载荷、材料、连接和变形依据，不按名称判断 |
| 八颗螺钉只有数量，没有位置、连接双方或配套孔 | 不接受为详细连接规格，逐实例补齐设计 |
| 同一计算被三个 AI 改写成三份“独立证据” | 识别同源，只保留实际证据力度与缺口 |
| 大量低风险小件共同阻挡排液或磨损线缆 | 全量底线与路径耦合检查提出问题，不能全部免查 |
| 每个零件尺寸自洽，全局功能基准链不闭合 | 反驳独立重建对应链，回阶段五、六修正 |
| 裸机能调整，外罩和管线装齐后工具进不去 | 7.9 联合状态推演暴露可达性问题，修改结构或装拆方案 |
| 没有分布数据，却靠统计公差放宽配合 | 不接受统计依据；核对有来源的边界或保留数据缺口 |
| 两家型号一样，但轴肩、孔位公差或配置不同 | 按实际接口检查；未核实来源不计入可互换范围 |
| 用户要直接换件，设计只注明“允许现场配作” | 判为需求冲突，不能靠如实注明就自行降低要求 |
| 设计只适用冷态洁净环境，现场会变热或污染 | 明确变化影响、适用边界与所需结构和检测条件 |
| 共用数据的计算与已有试验相互吻合 | 标同源性，不扩大到未覆盖的物理机理和输入范围 |
| 修改载荷后仍使用旧螺钉组、基准或结构结论 | 7.11 使相关结论过期并复审，不能只更新文字 |
| 问题需要尚不存在的真实对象才能回答 | 保留对应设计缺口及影响，不要求先完成其他环节，也不伪造通过 |
| 只有部分模块达到详细设计深度 | 交接注明实际范围，不宣称整机内部完整 |
| 换成陌生、多工位、多能源或大量零件的任务 | 按任务与机理展开层级和接口，不套教学设备的固定零件清单 |

## 本版结束位置

**V0.3 到前七阶段设计规格输出为止。** 核心是让 AI 把真实任务一步一步变成有依据、内部完整、接口清楚、可以继续工作的设计；其他环节由各自负责方处理，不在本文件编排。
