# A02 offline assembly contract (partial implementation)

SI and right-handed column vectors agree with A01. Joint origin maps joint coordinates to parent-link coordinates; URDF joint axis is in joint coordinates. No axis permutation or second scaling here.

Implemented: snapshot-local candidate mapping and reverse lookup; merged bodies return all candidates. Source revision, configuration and generation must match. This is NOT persistent identity resolution or write authorization. Names/source file paths are never promoted to persistent references. Before any future write, a SW adapter must resolve captured opaque references in the owning assembly document, check API error/object type and component occurrence/configuration, then revalidate the current source snapshot. Byte equality alone must not substitute for API resolution after rebuild. Missing references remain missing.

classify_motion consumes a complete solved relative-motion result, not raw mate names. 0 translation/0 rotation = fixed; 0/1 = revolute candidate; 1/0 = prismatic candidate. Other DOFs, incomplete/overconstrained/unknown solver state are rejected. Axis geometry, limits and global mobility are not proven by counts. Raw SW mate extraction/solver adapter is NOT implemented.

validate_tree rejects duplicate IDs, missing endpoints, multiple parents, loops and disconnected assemblies. No edge deletion or automatic spanning tree. Webots R2025a SolidReference supports explicit mechanical closure under a common upper Solid, but this A02 converter does not implement or validate it: closed loops UNSUPPORTED, physical closure NOT TESTED.

Existing single_revolute/prismatic fixtures are synthetic; they are not SW mate captures. No real SW rebuild/configuration mapping or physical sensor evidence exists. G1 PARTIAL remains unchanged.

It is only safe behind a trusted adapter; arbitrary caller JSON cannot establish identity. After rebuild/configuration change create a fresh snapshot and re-resolve; old snapshots fail. validate_joint checks finite explicit SI geometry/unit axis/ordered limits, not physical actuation.

Follow-up official verification resolves part of the earlier gap: EntityParams coordinates are in the assembly WHERE THE MATE RESIDES (not necessarily root assembly). SW 2018 EntityParams docs specify point xyz then direction/normal ijk then radii depending on point/line/plane/cylinder/cone. URL: https://help.solidworks.com/2018/English/api/sldworksapi/SOLIDWORKS.Interop.sldworks~SOLIDWORKS.Interop.sldworks.IMateEntity2~EntityParams.html . Therefore root-transforming these as component-local is wrong; capture must retain owning mate assembly before solving nested mates. Current raw capture deliberately leaves this context unresolved and cannot feed automatic joint inference.

Minimal solver now implemented: solve_captured_mates maps native concentric=1/cylinder=4 and coincident=0/plane=3 EntityParams to exact coaxial+axial-plane constraints. Concentric unlocked + coincident axial planes -> revolute; locked concentric -> prismatic; locked + axial planes -> fixed. Pure concentric unlocked (cylindrical two DOFs), unsupported mates, duplicate primitive constraints, wrong occurrence pair/frame, noncoincident axes and nonaxial planes reject. No general constraint solver. Caller must provide complete active bundle, owning_frame and native feature LockRotation; raw capture alone deliberately cannot satisfy this gate. Results axis/point remain in owning assembly frame, NOT directly URDF joint frame. Limits still explicit and separately validated.
