# A04 isolated runtime and physical gate

Production support is opt-in on Windows. The existing server and 17 schemas are retained. Default/unconfigured mode remains side-effect-free. Only an operator-approved, locally controlled world, its dependencies, controller, robot name and simulator installation may enter this mode. World and executable pins detect changed files; a world file hash alone does not authenticate external meshes, PROTOs, plugins or their behavior. Bind the complete approved project/model closure upstream. Do not run untrusted worlds.

The CLI option is `--runtime-config <operator-owned JSON>`. The existing explicit input root and state directory still apply. A configuration contains `webots_home`, `binary_sha256` with SHA256 entries for `webots.exe` and `webots-controller.exe`, `kernel_relative_path` and `kernel_sha256` identifying the actual native engine inside that installation, `worlds` keyed by the exact input-relative WBT path with `sha256`, `model_sha256` and `robot`, and a nonempty `limits` object with measured `process_count` (integer 1..64), `wall_time_s`, and `private_bytes`. Additional S05 metrics are accepted only when the sampler actually supplies them. Unknown metrics fail closed. No default physical budget, calibrated hardware or enabled host preset is supplied.

## Execution and recovery

* One live server per state root, one runtime session, at most 16 queued/executing jobs. Each mutation gets a durable SQLite intent and a separate dispatch commit. The same operation ID and semantic arguments retrieve the existing job even after restart. Different arguments conflict. Request ID is correlation only.
* The existing CLI selects the official external-controller launcher, matching the S03/S08 diagnostic path. A private Windows Job receives the suspended Python bootstrap before it is resumed. Children inherit the Job. The bootstrap drains both native streams continuously, retaining at most 64 KiB per stream; only an exact owned stdout IPC URL enables controller launch. The live credential, world path/hash, run/generation, port, robot, local interpreter and Job membership identify the controller. PID, creation time and actual executable are recorded in the owned generation directory. Read access to another process is never permission to kill it.
* `sim_step` and native API calls use one serial controller. Waiting tool callers do not hold the MCP loop. Status is cached; the JSON projection includes expiry and must be treated as stale after that time. The watchdog samples at 250 ms, the UI projection at most about once per second while idle, each action has a 30 s execution deadline. The process limit is also enforced by the OS; discrete memory/CPU samples do not certify peaks, GPU or step-only cost. A below-normal priority class is used.
* `sim_job` uses the original run/generation/job. A successful cold `sim_reset` tears down the old Job and binds the same pinned world to a fresh worker and new generation (reported as `data.new_generation`). Cached handles cannot cross it. Shutdown waits for the owned process tree, not the launcher alone. Cancel is independent of the step queue. An acknowledged cancel never asserts rollback. Interrupted accepted work stays unstarted. Dispatched, unconfirmed results remain unknown, with last durably confirmed time/step, even when a retry uses a new transport request ID. On restart the state projection is stale, no old simulation is resumed, and no persisted PID is killed. Inspect the existing operation/job; a separately authorized reproducible experiment needs new IDs.
* Per-generation bounded native logs and identity are inside the existing `webots_runs/<run>/worker/<generation>/` exclusion. `sim_job` returns immutable receipt(s) for native actions. `sim_evidence` pages a bounded per-run index log, and `sim_report` can read the initial unknown experiment report. I01's single report writer may assemble calibration/paired experiment reports from those receipts. No packaged runtime or DSH configuration was installed.

## Physics contract

`physical_gate.sample_from_observations(store,run,receipts,sensor=...,unit=...,pairs=...)` decodes a position sensor (m or rad) and exact Solid contact endpoints at the identical run, world, model, generation, simulation step and time. It checks both ends, the actual stored bytes and source kind. For this recipe, stability_error is peak monitored angular speed in rad/s. Select it only for a test whose calibrated limit measures that quantity; fast intended motion requires a different explicitly justified stability measure.

`physical_gate.evaluate(coarse,fine,policy)` accepts two distinct complete step-by-step traces of the same robot, equal duration/seed and halved step. Both bind the model, scene excluding step, actions, initial state, materials, calibration, feedback binding, coverage and policy. Each pair needs distinct bodies, calibrated shapes, positive detector control and no filter; self pairs require selfCollision. Consecutive solids and shared-anchor chains can still be filtered. A03 verifies that each per-run coverage attachment's run/generation/robot/world and actual pair fields match the trace. The evaluator rejects unequal interval occupancy, incompatible metric/units/threshold classifications, unbounded/nonfinite behavior, cal/feedback gaps and unsupported topology. Finite sample coverage is limited to the measured steps and selected pairs. Closed loops, deformable bodies, strength/fatigue, uncalibrated detector scope, general conversions and exact physical-state resume are outside this implementation.

Synthetic inputs return `verdict=UNKNOWN` even if numerical criteria succeed. A physically credible FAIL can describe an actual design issue. Raw evidence provenance must come from the trusted producer and verified owned store; copying literal strings into JSON is not measurement. Public online evidence and local fixture results do not authorize a real simulator launch.
